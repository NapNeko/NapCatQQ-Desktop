## 1. 我们是谁、本说明覆盖什么

1.1 NapCatQQ Desktop 是一款**自托管 Windows 桌面应用**，用于在您自己的电脑上管理本机与远端的 Bot/组件/部署任务。  
1.2 维护者**默认不运营**面向终端用户的云端账号系统，也**不以「收集您的 QQ 消息/好友列表做产品分析」为目的**处理您的业务数据。  
1.3 本说明回答三件事：  
- 软件在您设备上会存什么；  
- 哪些情况下数据可能离开本机；  
- 维护者与您在个人信息保护中的**角色如何划分**。

## 3. 本机存储的信息类型

为实现功能，本软件可能在您本机权威数据目录（通常为 `%ProgramData%\NapCatQQ Desktop`，可被 `NCD_DATA_ROOT` 等机制覆盖）及系统凭据库中存储：

### 3.1 应用与偏好
- 界面主题、动画、关闭行为、托盘/轻量模式等偏好；  
- 轮询间隔、性能监视开关、任务队列清理策略；  
- 开机自启等系统集成偏好。

### 3.2 运维配置
- Bot 实例配置（后端类型 NapCat/SnowLuma、本机或远端、Native/Docker 等）；  
- 远端主机档案（地址、端口、用户名、认证方式、主机指纹确认状态等）；  
- Docker 相关元数据、部署任务与进度记录；  
- 组件检测结果与安装状态缓存。

### 3.3 敏感凭据（高敏感）
- SSH 密码、私钥口令；  
- GitHub PAT（用于访问发行版/组件源等，如您填写）；  
- WebUI 口令覆盖、Webhook Secret、邮件通道凭据等。  

> 实现上会尽量使用系统凭据库或受控 secrets 目录，**避免明文散落**；但这不构成绝对安全承诺。

### 3.4 日志与诊断
- 桌面应用日志、Bot 日志拉取缓存、错误信息；  
- 离线通知投递历史（成功/失败记录）；  
- 崩溃或异常堆栈（如本地产生）。

### 3.5 协议同意记录
- 您对本软件 EULA / 本说明的同意版本（内容指纹）与时间，写入如 `config/desktop-consent.json`。

### 3.6 管理对象中的业务数据（由您控制）
通过本软件启动的 NapCat/SnowLuma/QQ 等，可能在其**自己的数据目录**中存储账号会话、好友/群、消息缓存等。  
**该类数据不属于维护者收集，而属于您运营行为的结果**；请同时阅读对应上游的隐私说明（如 SnowLuma 的 PRIVACY）。

- 向您交付软件与更新；

- 履行法定义务。

在《个人信息保护法》框架下，维护者若处理个人信息，可能依赖的合法性基础包括：**订立/履行合同所必需**、**法定职责义务**、或在适用时的**同意**。  
**您作为处理者**处理好友/消息等数据时，须自行确保具备合法基础（通常涉及告知同意、合同必需等，视场景而定）。

## 5. 数据可能离开您本机的情形

除下列情形外，本软件**不会主动**把您的 Bot 业务数据、SSH 密钥或消息内容回传给维护者：

### 5.1 您主动配置的外发通道
- 离线 Webhook / 邮件 / OneBot 等通知；  
- 内容、收件地址、密钥均由您填写；维护者不经手审核。

### 5.2 版本检查、更新与组件下载（含中转与镜像）
为便于在网络受限环境下获取版本信息与安装包，本软件可能访问下列端点（以实际构建与配置为准）：

1. **版本/发行信息中转服务（如已在发行包中启用）**  
   - 用途：代查 NapCat、SnowLuma、本软件（Desktop）、ncd-watch 等仓库的 **GitHub Releases 元数据**（版本号、资源列表等），改善可达性并降低直连 GitHub API 的限速影响。  
   - 请求一般为发行信息查询，**不是**上传您的 Bot 配置、QQ 消息、SSH 密钥或好友资料。  
   - 请求侧可能产生的技术信息包括：访问时间、源 IP、`User-Agent`（可含本软件版本）、签名用时间戳等；中转服务端可能记录访问日志以便防滥用与排障。  
   - 中转未配置、不可用或失败时，会 **回退直连 GitHub 官方 API**（若您填写了 GitHub PAT，仅用于该直连回退，**不会**把 PAT 发给中转）。  
   - 本机可能保存与中转时钟校准相关的偏移量（如配置目录下的时钟偏移文件），用于签名请求，**不含业务内容**。

2. **GitHub 及第三方下载镜像**  
   - 下载 MSI、组件包、框架资源等时，可能对 GitHub 资源 URL 使用内置或候选的 **第三方反向代理/镜像**（与版本中转可以不是同一套服务），以便加速或提高成功率；也可能直连官方地址。  
   - 镜像运营方独立处理其访问日志，适用其各自政策。

3. **共性**  
   - 上述请求中可能包含：软件/组件版本、操作系统与 CPU 架构、时间等**技术性信息**；  
   - **不包含**您的 QQ 账号会话内容、消息正文、SSH 私钥明文等业务机密（除非您另行把此类内容写进自己配置的通知通道，见 5.1）。

### 5.3 您打开的外链
- 关于页打开仓库、License、文档等，由系统浏览器访问目标站点。

### 5.4 远端运维
- SSH 连接、文件同步、Docker 部署、日志跟随、隧道等，数据在**您的电脑与您指定的服务器**之间传输；  
- 就您的业务运维链路而言，维护者不是中间人（版本中转仅处理发行元数据查询，见 5.2）。

### 5.5 您向社区提交的信息
- 您在 GitHub Issues/PR 中粘贴的日志可能含路径、主机名等，请自行脱敏。

## 6. 维护者不做的事（负面清单）

在当前设计下，维护者**不会**：

- 要求您注册维护者云账号才能用核心本地功能；  
- 将您的 QQ 消息、好友列表、群成员资料作为产品遥测上传；  
- 出售您的个人信息；  
- 在未说明的情况下引入第三方广告追踪 SDK（本软件为桌面工具，非广告应用）。

9.1 本机数据的保存期限由**您**控制：您可删除 Bot、清理日志、卸载软件或直接删除数据目录。  
9.2 同意记录建议随配置保留，以便证明您曾确认的版本；您可手动删除 `desktop-consent.json`（删除后可能被要求重新确认）。  
9.3 维护者若仅在 issue 中收到您主动发送的信息，将按社区运营需要保存，并在您请求且可行时删除。

## 10. 安全措施

10.1 软件侧采取的合理措施包括但不限于：本地数据目录分离、敏感项优先凭据库存储、权限最小化设计、更新包校验（如版本已实现）等。

10.3 发生疑似泄露时，请立即轮换 SSH/PAT/Webhook 密钥，并检查远端主机。
