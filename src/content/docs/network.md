下载组件很慢时，先看卡住的请求发生在哪里：Desktop 下载 QQ 安装包，与服务器拉 Docker 镜像，用的是两套网络配置。本页先解决 Desktop 自己发起的下载和版本查询；远端相关问题见 [远端 Linux](/docs/remote-linux/) 和 [Docker 部署](/docs/docker/)。

## 先完成一次连接测试

1. 打开「设置 → 网络」。
2. 如果没有专门的代理服务，先保留「代理模式 → 跟随系统」，GitHub、Node.js 下载线路保留「自动选择」。
3. 滚动到「连接测试」，点击「测试连接」。
4. 查看各项的成功或失败、HTTP 结果和响应耗时。测试会用当前填写的草稿，暂时不会修改已保存设置。
5. 确认结果合适后点击「保存设置」，再开始新的下载。

![代理、下载线路和 GitHub API 分开配置；截图使用客户端演示数据。](/docs/screenshots/settings-network-light.png)

**完成后应看到什么：** GitHub API 与下载候选地址分别有测试结果；保存后，新发起的下载使用新的配置。已经开始的下载继续使用开始时的代理和线路，需要等它结束或按任务提供的操作停止后再试。

连接测试显示的毫秒数是响应耗时，不是每秒能下载多少数据。「自动选择」在真正下载时还会比较吞吐量，所以不要只凭这里的最小毫秒数固定一个镜像。浏览器中的开发演示不能执行真实网络测试，请在 Windows 客户端中操作。

## 已有代理软件，怎样填写

先打开代理软件，找到它提供的本地 HTTP 或 SOCKS 监听地址。下面的端口只是填写示例，必须改成你自己的端口。

1. 在「代理模式」选择「手动配置」。
2. 「代理地址」填完整协议和地址，例如 `http://127.0.0.1:7890`。
3. 如果代理要求认证，分别填写「代理用户名（可选）」和「代理密码（可选）」。地址里不要再拼用户名或密码。
4. 如果局域网服务要直连，在「不使用代理的地址」中填写主机名、域名、IP 或网段，用英文逗号分隔。例如 `localhost,192.168.0.0/16`。
5. 点击「测试连接」。有字段错误时，先按字段下方提示修正。
6. 测试符合预期后「保存设置」，重新发起下载。

| 代理地址形式 | 域名在哪里解析 |
| --- | --- |
| `http://127.0.0.1:7890`、`https://…` | 按相应 HTTP 代理协议处理 |
| `socks5://127.0.0.1:1080` | 由本机解析目标域名 |
| `socks5h://127.0.0.1:1080` | 由代理解析目标域名 |

本机回环地址始终绕过代理。代理密码保存在系统密钥库或本机加密存储中，不写进普通设置文件，也不会随配置 ZIP 导出。换机后需要重新填写。

### 三种代理模式怎么选

| 界面选项 | 适合什么情况 |
| --- | --- |
| 跟随系统 | 希望沿用 Windows 固定代理或代理环境变量；不执行 PAC 自动代理脚本 |
| 不使用代理 | Desktop 外网 HTTP 请求直接连接，忽略系统代理 |
| 手动配置 | 明确指定 Desktop 使用的 HTTP、HTTPS、SOCKS5 或 SOCKS5H 代理 |

如果浏览器能上网、Desktop 却不能，检查系统是不是只配置了 PAC。PAC 不会由「跟随系统」执行，可改用代理软件提供的固定地址。

## GitHub 和 Node.js 下载线路

两项分别设置。GitHub 线路主要用于已知的公共 GitHub 下载，Node.js 线路用于 Node 官方二进制包。

| 界面选项 | 下载时会怎样做 |
| --- | --- |
| 自动选择 | 比较候选源实际速度；低速或失败时尝试其他候选。使用手动代理时，自动线路走原站，通过指定代理连接 |
| 仅原站 | 使用官方原地址，仍遵循上面的代理设置；失败时不自动换站 |
| 指定镜像 | 只使用选中的内置镜像或自定义地址；失败时不自动换站 |

通常先用「自动选择」。如果确实知道某个镜像在当前网络稳定，再切到「指定镜像」。进度中可以看到当前源的主机名、速度和自动换源原因；换源会重新下载，避免把不同来源的内容拼成损坏的安装包。快下载完时，Desktop 会根据剩余时间决定是否继续当前下载。

### 填写自定义镜像

1. 将对应「下载线路」选为「指定镜像」。
2. 在镜像列表选「自定义地址」。
3. 根据下载类型填写地址，再测试并保存。

| 类型 | 地址应该填什么 | 例子 |
| --- | --- | --- |
| GitHub | 镜像前缀，后面会自动追加完整原 URL | `https://mirror.example` 会组成 `https://mirror.example/https://github.com/owner/repo/...`；这是格式示例，不是可用镜像推荐 |
| Node.js | 包含版本目录的 dist 根地址 | `https://registry.npmmirror.com/-/binary/node`，版本路径由 Desktop 追加 |

带账号密码、查询参数或签名的链接，以及其他下载站点，不会被转发到这些镜像；它们仍按代理设置访问。不要把任意网页地址当成下载镜像根地址。

## GitHub API 与安装包线路有何区别

「GitHub API」查询版本等元数据；「GitHub 下载线路」负责公共安装包下载。能看到新版本但下不动包时，优先检查下载线路，而不是反复更换 API 设置。

1. 在「GitHub API → API 访问方式」选择「默认中转，失败后尝试原站」或「仅 GitHub 原站」。
2. 匿名额度够用时，「Personal Access Token（可选）」留空即可。
3. 如果需要使用自己的 GitHub API 额度，填写自己的 PAT，测试并保存。

PAT 只发给 GitHub API，不发送给 API 中转或下载镜像。它保存在系统密钥库或本机加密存储，配置包不会替你把这份凭据带到另一台电脑。截图或反馈网络问题时，保留错误文字即可，隐藏 Token 和密码。

## 这项设置管不到哪些请求

| 请求发生在哪里 | 应该在哪里处理 |
| --- | --- |
| Desktop 下载组件、更新包、查询版本 | 本页的网络设置 |
| 本机 Bot / WebUI | 对应 Bot 或协议端的配置 |
| SSH 连接 | 远端主机档案、网络路径和 SSH 配置 |
| Linux 上的 `curl`、`wget`、包管理器 | 对应远端系统的网络配置 |
| 远端 Docker 拉镜像 | 远端 Docker 环境与界面提供的镜像源 |
| 框架或插件自己访问 API | 框架或插件自己的代理与网络设置 |

因此，Desktop 测试全部成功而远端任务仍报下载失败时，接着看远端任务日志中的域名和命令。它不代表这页的代理没有保存。

## 按错误继续检查

- **代理连接被拒绝：** 检查代理软件是否启动，以及协议、IP、端口是否与其监听设置一致。
- **代理认证失败：** 检查独立的用户名、密码字段及代理端的认证设置。
- **指定镜像失败：** 先检查镜像地址格式；仍不可用时，换另一个可用镜像或改回「自动选择」。指定镜像不会自动帮你换源。
- **测试成功但下载慢：** 观察实际下载进度的速度与当前源；响应快不代表大文件吞吐量高。
- **保存后正在下载的任务没变化：** 当前任务沿用原设置。下一次请求才使用新配置。
