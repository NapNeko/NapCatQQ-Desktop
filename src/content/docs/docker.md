Docker 镜像包含 QQ 所需的依赖，无需在服务器上逐一安装。Desktop 的 Docker 部署只支持远端 Linux；本机和远端 Windows 使用原生运行，本机安装 Docker 也不会出现这个部署选项。

如果还没添加服务器，先按 [远端 Linux](/docs/remote-linux/) 把主机加好、SSH 测通，再回来看这一篇。

## 1. 准备 Docker

1. 打开「组件」，切到要部署的那台 Linux 主机。
2. 在运行时依赖里找到 Docker，等它探测完。
3. 还没装的话点「安装」，按提示提供提权信息，在「任务」里看进度。
4. 装完以后重新检测一下，确认 Docker 已经就绪。

侧栏里的「容器」入口要满足两个条件才会出现：至少有一台远端主机上的 Docker 可用，并且「设置 → 功能 → 容器页」是开着的。

光装好 Docker 还不够，SSH 登录的那个用户还得有权限用它。用同一个用户在远端终端里运行：

```bash
docker info
```

能看到服务端的信息就没问题。如果提示连不上 Docker daemon，检查一下 Docker 服务有没有启动；如果提示 `permission denied`，那是用户权限的问题，重试拉镜像是解决不了的。

可以请服务器管理员把这个用户加进 `docker` 组，然后退出、重新登录，权限才会生效：

```bash
sudo usermod -aG docker "$USER"
```

`docker` 组权限很大，可以控制宿主机上的所有容器。请只授予用于管理服务器的账户。

## 2. 拉取协议镜像

1. 组件页保持选中这台 Linux。
2. 找到 NapCat 或 SnowLuma，点这一行的「拉镜像」。
3. 默认会自动选镜像源；某个源用不了，可以在「选择镜像源」里换一个。
4. 在「任务」里看拉取进度，完成后确认镜像已经就绪。

拉取镜像不会创建 Bot。镜像已包含容器所需依赖，无需按原生部署清单安装宿主机依赖。

「设置 → 网络」里的 GitHub / Node.js 下载线路管不到 Docker 拉镜像。拉得慢的话，要去查这台 Linux 自己的网络，以及这里选的镜像源，见 [网络作用范围](/docs/network/)。

## 3. 创建 Docker Bot

1. 到「机器人」新建一个 Bot，填 QQ 账号和实例名称。
2. 选刚才拉了镜像的 NapCat 或 SnowLuma。
3. 「运行场景」选远程运行，「目标远程主机」选这台 Linux。
4. 「启动方式」选「Docker」，确认界面上显示 Docker 和镜像都已就绪。
5. 保存，从卡片上启动，打开日志等协议端起来。
6. NapCat 用 WebUI 登录；SnowLuma 用「扫码登录」或者 VNC，见 [扫码登录](/docs/remote-login/)。

请分别确认容器运行、QQ 登录和 OneBot 连接三个状态。容器运行中不代表账号在线。

## 4. 端口：容器内和宿主机

打开侧栏「容器」，选这台主机，在容器卡片上能看到端口映射；点「详情」可以看完整的端口和挂载信息。也可以在远端终端里运行：

```bash
docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

举个例子，映射显示宿主机的 `6388` 转发到容器里的 `6099`。那么从宿主机访问要用 `6388`，只有在容器内部才用 `6099`。这只是个例子，你的端口以实际的映射为准。

| 谁发起连接 | `127.0.0.1` 指哪里 | 要检查什么 |
| --- | --- | --- |
| Windows 上的 Desktop / 浏览器 | Windows 本机 | 用 Desktop 提供的入口或隧道 |
| Linux 宿主机上的应用 | Linux 宿主机 | 容器端口有没有发布到宿主机 |
| 同一个容器里的进程 | 这个容器 | 协议服务是否监听在容器内的地址 |
| 另一个容器里的应用 | 那个容器自己 | 两个容器的共同网络和实际服务地址 |

想让宿主机或者其他容器能访问到协议端，容器里的服务一般要监听 `0.0.0.0`，再配合端口发布或者容器网络。如果服务只监听了容器内的 `127.0.0.1`，那即使做了端口映射，宿主机也访问不到。OneBot 的地址、方向和 token 怎么配，见 [连接指南](/docs/connections/)。

## NapCat WebUI 提示 token 错误

已有容器的有效 token 以当前使用的 `webui.json` 为准，不一定是最初启动参数中的值。Desktop 会读取实际配置，并在鉴权失败后重新核对。

先把 Desktop 更新到最新、重新连接一下 Bot。还是不行的话，检查 SSH 用户能不能执行 Docker 命令、能不能读到容器的配置，再看看 WebUI 是不是提示了限流或者需要两步验证。

## 容器页

「容器」页按主机列出「容器」「镜像」「网络」「数据卷」，搜索框可以按名称、ID 等过滤。操作前请确认选中的服务器。

- 容器：根据状态启动、停止、暂停、恢复或重启；「日志」读的就是 `docker logs` 的内容。
- 详情：退出码、是不是因为内存不足被终止、重启了几次、健康检查、网络、端口和挂载。容器在运行时，还能看 CPU、内存、网络和磁盘读写。
- 镜像：确认需要的镜像在不在，清理之前看清楚它还被谁引用着。
- 网络与数据卷：看容器用的是哪个网络、数据持久化在哪里。还被容器引用着的，不能直接删。

删除容器只会丢掉它的可写层，挂载的数据卷和宿主机目录都还在；但删除数据卷，就会永久删除卷里的内容。配置 ZIP 不包含容器数据、应用数据库或程序，清理前先确认数据存在哪里，并单独备份。

## 启动失败时看这三样

1. 容器页里，这个容器是不是已经退出了，退出码是多少。
2. 「日志」里第一条真正的错误，而不是最后一行的汇总。
3. 端口映射和挂载，和你当前的配置对不对得上。

看到 `内存不足终止：是`，先解决服务器内存不够的问题；看到 `permission denied`，查执行用户和目录权限；账号没登录，就回登录入口去处理。不是所有问题都是镜像没拉好。

需要在 Desktop 退出后继续监控容器中的账号，可以安装 [ncd-watch](/docs/watch/)。它会读取容器和 WebUI 中的账号状态；`docker ps` 不能判断 QQ 是否掉线。
