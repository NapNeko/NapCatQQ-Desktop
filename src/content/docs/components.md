「组件」页用于管理各台主机上的程序和依赖。Bot 的运行、登录状态在机器人卡片上查看；安装组件后还需要创建 Bot。

## 先选主机

1. 打开「组件」。
2. 在主机切换区选「本机」，或者已经添加过的远端主机。
3. 核对一下主机名和系统类型，再去安装、更新或卸载。

![组件管理：每台主机分别检测和安装组件](/docs/screenshots/components-light.png)

每台主机的组件单独检测和安装。本机装了 NapCat，远端也需要单独安装。远端主机无法连接时，组件状态会显示未知，这不一定表示组件故障；请先到「远端」测试连接。

## 需要装哪些

| 目标 | 要准备的 |
| --- | --- |
| 本机 NapCat Bot | QQ、NapCat，以及安装时提示的运行时 |
| 本机 SnowLuma Bot | QQ、SnowLuma；依赖按 Full / Lite 准备 |
| 远端原生 Bot | 目标主机上的 QQ、协议端、运行时和 QQ 系统依赖 |
| 远端 Docker Bot | Docker 和协议端镜像，容器依赖由镜像自带 |
| 插件或 AI 应用 | 选一个框架建实例，运行时和依赖由安装任务准备 |
| Desktop 退出后的远端值守 | 在那台远端主机装 ncd-watch |

开始时安装一个协议端即可；需要插件或 AI 应用时，再按 [应用端实例](/docs/apps/) 安装框架。

## 安装

1. 选对主机，找到对应的卡片。
2. 看当前状态和可装的版本。
3. 点「安装」，在弹窗里选好选项。
4. 在卡片上或者「任务」页看下载、解压和安装的进度。
5. 装完等检测刷新，核对版本和状态。

同一个组件还在装的时候，别再点一次安装。能取消的任务会有取消按钮，取消以后等状态稳定下来再重试。

### QQ：NCD 管理和系统 QQ

组件页装的 QQ 和你电脑上原本的系统 QQ 是两份。如果 Bot 正在用系统 QQ，卡片上会出现「转为 NCD 管理」：点了会另装一份 QQ，Bot 下次启动时优先用这一份，系统 QQ 本身不受影响。

系统 QQ 要卸载的话，得去 Windows 的应用管理里卸，Desktop 只负责卸载它自己装的组件。另外，程序分开不代表登录数据完全隔离，启动前留意一下提示。

### SnowLuma：Full 还是 Lite

安装 SnowLuma 时会让你选：

- 完整版（默认）：自带运行时，以后升级也保持同一种包。
- Lite 精简版：包小一些，但不含 Node，安装时会顺带装上 Node.js。

没什么特别要求就选默认的完整版。选了 Lite 的话，要等 Node.js 也装好才能用。

### 应用框架按实例装

框架和 QQ 不一样，不是整台机器装一份大家共用。在组件页找到框架后要新建实例，选好主机和安装位置。同一个框架可以建好几个实例，每个都有自己的目录和依赖。

已经有现成项目的，用导入功能接管，别新建一个空实例去覆盖它，见 [应用端实例](/docs/apps/)。

### 远端 Linux 的系统依赖与 Docker

在 Linux 上原生运行 QQ 可能缺少动态库。组件检测会列出缺失项，按提示补齐；需要 sudo 时请使用有权限的账号。Docker 部署则需要检查 SSH 用户的 Docker 权限和镜像，不必安装原生运行所需的依赖。

详见 [远端 Linux](/docs/remote-linux/) 和 [Docker](/docs/docker/)。

## 更新

1. 记下当前版本，看看卡片上的「查看发版日志」或者上游的发布说明。
2. 导出配置。应用实例的数据库、插件程序这些要另外备份，见 [备份与数据](/docs/backup/)。
3. 停掉用到这个组件的 Bot 或实例。有 Bot 在运行时，部分更新和卸载按钮是禁用的，按钮上会写原因。
4. 点「更新」，等任务结束、检测刷新。
5. 先启动一个实例，确认登录、OneBot 连接和应用端都正常，再把其他的启动起来。

Desktop、协议端、应用实例的更新是三件独立的事。远端的 ncd-watch 也是单独发布的，升级 Desktop 不会顺带替换它。

## 状态不对时重新探测

组件状态有未安装、已安装、探测中、探测失败这几种。显示的和实际情况对不上时：

1. 等手头的安装或更新任务结束。
2. 在卡片上点「重新探测」，或者用页面上的刷新入口。
3. 远端主机先测一下 SSH，确认安装路径能访问、有权限。
4. 还是不对，就去看任务日志，记下组件、主机、版本和原始错误。

无法获取最新版本信息也可能只是发布信息查询失败，不代表已安装的程序有问题。

## 下载慢或失败

Desktop 自己发起的下载，走的是「设置 → 网络」里的代理和线路；远端的包管理器、Docker 拉镜像、框架自己下载东西，走的都是各自的网络。所以先弄清楚到底是哪一步在下载，再去改对应的地方，见 [网络设置](/docs/network/) 和 [任务与日志](/docs/tasks-logs/)。

装好以后去 [创建第一个 Bot](/docs/first-bot/)；已经有账号的，回 [机器人管理](/docs/bots/)。
