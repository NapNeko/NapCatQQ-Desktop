「组件」回答的是：**这台机器上有哪些程序，它们是否已经准备好。** Bot 卡片回答的是某个账号是否运行、是否登录。安装组件不会自动创建或登录账号。

## 先选主机，再操作组件

1. 打开「组件」。
2. 在主机切换区选择「本机」或你已经添加的远端主机。
3. 核对主机名称和系统类型，再点击安装、更新或卸载。

![组件管理：每台主机分别检测和安装组件](/docs/screenshots/components-light.png)

主机的组件状态分别保存和检测。在 Windows 本机装好了 NapCat，不表示 Linux 服务器也已经安装。远端主机不可达时，先去「远端」测试连接；连接失败时的一片未知状态，不是所有组件同时被卸载了。

## 第一次需要装哪些

| 目标 | 准备内容 |
| --- | --- |
| 本机 NapCat Bot | QQ、NapCat，以及安装流程提示的运行时 |
| 本机 SnowLuma Bot | QQ、SnowLuma；Full / Lite 依赖按选择准备 |
| 远端原生 Bot | 在目标主机准备 QQ、协议端、运行时和 QQ 系统依赖 |
| 远端 Docker Bot | Docker 和对应协议端镜像；容器依赖由镜像提供 |
| 插件或 AI 应用 | 选择框架并创建实例，由任务准备其运行时与框架依赖 |
| Desktop 退出后远端值守 | 在对应远端主机安装 ncd-watch |

不要为了“齐全”先装完所有框架。本机入门先准备一个协议端即可；想增加插件功能时，再按 [应用端实例](/docs/apps/) 安装对应框架。

## 安装一个组件

1. 选对主机，找到目标卡片。
2. 查看当前状态与可装版本。
3. 点击「安装」，根据弹窗选择安装选项。
4. 在卡片进度或「任务」页观察下载、解压和安装步骤。
5. 完成后等待检测刷新，确认版本和状态。

如果任务仍在执行，不要同时开另一个安装去覆盖同一组件。可以取消的任务会显示取消入口；取消后先等状态稳定，再重试。

### QQ：NCD 管理和系统 QQ

组件页安装的 QQ 程序与系统 QQ 分开。检测到系统 QQ 并使用它时，卡片可提供「转为 NCD 管理」：单独安装一份 QQ，Bot 下次启动时优先使用，不改动系统 QQ 程序。

系统 QQ 的卸载需要进入 Windows 应用管理；Desktop 自己管理的组件才按其支持的方式执行卸载。不要因为看见 QQ 已安装，就把它理解为登录数据完全隔离，启动前仍要核对程序提示。

### SnowLuma：Full 还是 Lite

安装 SnowLuma 时，选择框会提供：

- **完整版（默认）**：自带 SnowLuma 所需运行时，升级沿用当前包类型。
- **Lite 精简版**：包体更小，不含 Node；安装任务会自动安装 Node.js。

第一次使用可以保持默认。Lite 不代表功能配置可以忽略运行时，仍要等待其依赖任务完成。

### 应用框架：按实例安装

应用端框架不是给整台主机只装一份、所有配置共用。在组件页找到对应框架后，新建一个实例，选择主机和安装位置；同一框架可以有多个实例，各自管理安装目录与依赖。

已有项目应从导入入口识别，而不是把目录当作一个新空实例覆盖。详细步骤见 [应用端实例](/docs/apps/)。

### 远端 Linux 的系统依赖与 Docker

原生 QQ 运行可能缺少动态库，组件检测会给出提示。按检测结果补齐依赖；需要 sudo 时使用你有权限的账号完成操作。Docker 则检查 SSH 用户能否使用 Docker、镜像是否准备好，不要把原生 QQ 的全部依赖清单照搬到容器方案。

相关操作见 [远端 Linux](/docs/remote-linux/) 和 [Docker](/docs/docker/)。

## 更新组件前后检查什么

1. 记录当前组件和协议端版本，查看卡片提供的「查看发版日志」或上游发布说明。
2. 导出配置；应用实例数据库、插件程序等另行备份，范围见 [备份与数据](/docs/backup/)。
3. 停止依赖这项组件的 Bot 或实例。存在活跃 Bot 时，某些更新和卸载操作会被禁用，请先看按钮提示。
4. 点击「更新」，等待任务结束与检测刷新。
5. 重新启动一个实例，确认 QQ 登录、OneBot 连接与应用端功能，再恢复其他实例。

Desktop 的更新、协议端的更新、应用实例的更新是不同操作。远端 ncd-watch 也独立发布，升级 Desktop 不会自动替换远端的值守程序。

## 状态不对，先重新探测

组件可能尚未安装、已安装、正在探测，或探测失败。遇到状态与实际不一致时：

1. 等当前安装或更新任务完成。
2. 在对应卡片使用「重新探测」，或按页面提供的刷新入口检测。
3. 远端先测试 SSH，确认安装路径和权限可访问。
4. 仍失败时查看任务日志，记录组件、主机、版本与原始错误。

没有远端版本信息，不一定表示本机程序损坏；也可能是发布信息请求失败。不要用反复卸载来处理单纯的版本查询问题。

## 下载慢或失败

组件下载受 Desktop 的代理和下载线路配置影响；远端包管理器、Docker 拉取和框架自己发起的下载则各有网络环境。先确定哪个步骤在下载，再调整对应网络。详见 [网络设置](/docs/network/) 与 [任务与日志](/docs/tasks-logs/)。

安装完成后继续 [创建第一个 Bot](/docs/first-bot/)；已有账号则回到 [机器人管理](/docs/bots/)。
