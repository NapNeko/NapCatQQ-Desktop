Desktop 留在你的 Windows 电脑上，QQ 和协议端运行在 Linux 服务器上。连接服务器用的是 SSH；不需要在 Linux 上安装 Desktop 客户端。

这一页先完成一个**远端原生 Bot**。如果打算用容器，添加并测试主机后，转到 [Docker 部署](/docs/docker/)。

## 先准备这些信息

| 信息 | 从哪里确认 | 示例 |
| --- | --- | --- |
| 主机地址 | 云服务器控制台、局域网管理页或管理员 | `192.168.1.20`，请换成你的实际地址 |
| SSH 端口 | 服务器的 SSH 配置 | 常见为 `22`，也可能已修改 |
| 用户名 | 创建服务器时设置的 Linux 用户 | `ubuntu`，不要照抄不属于你的用户名 |
| 认证方式 | 服务器允许的密码或私钥 | 私钥填写 Windows 本机上的私钥文件 |
| 安装权限 | 该用户能否写入安装目录、安装依赖 | 系统依赖可能需要 `sudo` |

先确认这台 Windows 电脑能到达 SSH 地址。云服务器有安全组、主机有防火墙时，要允许你的连接来源访问实际 SSH 端口。仅在云控制台里看到「运行中」，不能说明 SSH 已可用。

如果没有指定发行版，可以从常见的 Ubuntu / Debian 环境开始。是否缺少 QQ 动态库、架构是否匹配，以后面的组件检测为准。

## 1. 添加并测试主机

1. 打开侧栏的「远端」，点击添加按钮。
2. 在「添加远端服务器」中填入「名称」「主机地址」「端口」「用户名」。「名称」可以写成容易区分的 `家里的 Linux`。
3. 「目标系统」选择「自动识别」或「Linux」。
4. 在「认证方式」里选择「密码认证」或「密钥认证」。密码填 SSH 密码；密钥选本机私钥文件，不是 `.pub` 公钥文件。密码模式下若想先保留密码登录，取消「自动配置免密登录」；也可以按下一节在添加时一起配置免密。
5. 保存档案，回到主机卡片点击「测试连接」。添加档案本身不会代替连接测试。
6. 第一次连接出现主机指纹时，和服务器管理员提供的指纹核对，再信任这台主机。

![添加远端服务器时填写主机、系统与认证方式](/docs/screenshots/remote-create-light.png)

测试成功后再继续。地址写错、密码错误、连接超时是不同问题，按测试结果处理。编辑已有档案时，密码框留空表示保留原凭据；不是清空密码。

已经有 SSH 配置的用户，也可以使用远端页的「从 SSH 配置导入」，导入后仍要核对地址、用户名并测试连接。

### 把密码登录改为免密登录

免密登录使用本机私钥证明身份，不是把服务器的 SSH 认证关闭。Desktop 可以为这个档案生成专用密钥，并把公钥写到目标用户的 `authorized_keys` 中。

1. 先用密码测试连接，核对首次出现的主机指纹，确认用户名、密码和连接目标正确。
2. 在这张远端卡片点击钥匙图标「配置免密登录」，或右键卡片选择同名操作。这个入口在档案仍使用密码认证时提供。
3. 在弹窗填「当前 SSH 密码」，点击「配置免密」。这次会再次用密码验证连接；如果尚未信任主机指纹，先核对并信任后才能继续。
4. 等待「免密登录已配置」提示。Desktop 会生成密钥、写入远端公钥，再实际测试新私钥能否登录；成功后才把已保存档案自动切换为「密钥认证」，不需要手工再选一次。
5. 再点「测试连接」，确认新认证方式可用。在编辑档案时可以查看「私钥文件路径」。

如果验证新私钥失败，档案仍保留密码认证，按错误检查远端 SSH 公钥认证与目录权限，不要反复清除已有密钥。

**添加主机时一起配置：**在新建弹窗使用「密码认证」、填写密码并勾选「自动配置免密登录」，点击「添加」。Desktop 会先保存档案，再进行同样的密码测试、指纹确认和密钥配置；密码留空时只添加档案，不会自动配置。SSH 连接或免密失败时仍要查看具体结果，不能只凭卡片出现就当作免密已经成功。

自动生成的私钥保存在本机数据根下的 `ssh_keys` 目录，配置 ZIP 不包含 SSH 私钥。换电脑时另行妥善迁移私钥，或使用仍可用的密码重新配置；不要把私钥内容贴进日志反馈，也不要把配置包当成完整的 SSH 登录备份。更多见 [备份与恢复](/docs/backup/)。

## 2. 把组件装在这台服务器上

1. 打开「组件」，在主机选择器中切换到刚才添加的 Linux 主机。
2. 看清当前主机名称，再检查 QQ、NapCat / SnowLuma 和对应运行时的检测结果。
3. 安装缺少的组件。原生运行需要目标 Linux 上的 QQ 及协议端，控制端 Windows 已安装的组件不能代替它们。
4. 安装过程中打开「任务」查看当前阶段。遇到缺少系统库或提权提示，按这台服务器的实际情况完成，不要同时反复提交相同任务。
5. 安装结束后刷新检测结果，确认所选协议端及依赖已经就绪。

如果服务器上已经装过组件，从「远端 → 库存」刷新探测结果，核对检测到的目录。路径属于远端 Linux，例如 `/home/ubuntu/...`；不要填入 Windows 的 `C:\...`。

![远端页按主机显示连接与库存入口](/docs/screenshots/remote-light.png)

## 3. 创建远端原生 Bot

1. 打开「机器人」，新建 Bot。
2. 填写「QQ 账号」和「实例名称」，选择已准备好的 NapCat 或 SnowLuma 底座。
3. 在「运行场景」中选择远程运行，再把「目标远程主机」设为这台 Linux。
4. 「启动方式」选择直接运行，核对界面展示的目标主机和组件状态。
5. 保存，回到卡片启动 Bot。
6. 打开卡片的日志入口，确认启动的确发生在目标服务器上。

现在只是把程序启动起来了。还要完成下一步 QQ 登录，才能使用消息相关功能。

## 4. 完成 QQ 登录

NapCat 使用 Bot 卡片提供的 WebUI 登录入口。打开后按页面提示获取二维码，用手机 QQ 扫描并确认，随后观察 Bot 卡片和日志中的账号状态。

SnowLuma 可点击卡片上的「扫码登录」。这一入口默认开启，但远端 Linux 需要 Python 3、AT-SPI、X11 和可用的会话 D-Bus。没有可用环境时，通过 QQ 图形界面 / VNC 完成登录，具体见 [SnowLuma 扫码登录](/docs/remote-login/)。

**完成后核对三件事：**进程仍在运行、QQ 账号已登录、OneBot 连接符合你的用途。只看到进程运行或 WebUI 能打开，还不能证明应用端已经连上。

## 5. 连接应用端

先读 [OneBot 连接](/docs/connections/) 选择 HTTP、正向 WebSocket 或反向 WebSocket。配置地址时，明确是谁向谁连接：

- 应用端与协议 Bot 都在同一台 Linux 上，地址里的 `127.0.0.1` 指这台 Linux。
- 应用端在另一台机器上，`127.0.0.1` 指各自所在的机器，不能用它代表远端服务器。
- 应用端在容器里，回环地址又属于容器本身，按 [Docker 的端口说明](/docs/docker/) 检查。

在 Desktop 配置好连接后保存；需要让协议端重新加载的设置，按界面提示重启。最后从应用端或调试台做一次实际请求，再发送一条测试消息确认事件能到达。

## WebUI 修改过的连接为什么又变回去了

Desktop 启动远端 Bot 时，会按自己保存的连接配置写入远端 OneBot 文件。直接在 NapCat / SnowLuma WebUI 里修改的内容，如果没有同步到 Desktop，下次启动可能被覆盖。

打开这个 Bot 的「配置 → 连接」，点击「从远端读取」，核对新增、删除与修改的差异，确认后填回表单并保存。之后再从 Desktop 启动。

## 安装或启动失败，按阶段查

| 停在哪一步 | 先查什么 | 下一步 |
| --- | --- | --- |
| SSH 测试失败 | 地址、端口、用户名、认证和网络路径 | 先让连接测试成功 |
| 组件安装失败 | 「任务」中的失败步骤、远端下载与权限 | 补齐依赖或修复下载后重试 |
| 进程启动即退出 | Bot 日志、QQ 动态库、实际组件路径 | 回组件页重新检查 |
| 进程运行，账号不在线 | WebUI / QQ 登录流程、手机确认 | 完成登录，不要重复创建 Bot |
| WebUI 打不开或鉴权失败 | SSH 连通性、实际 WebUI 端口和密码 | 重新连接并核对当前配置 |
| QQ 在线，应用端没反应 | OneBot 方向、地址、端口、token、适配器 | 按 [连接排错](/docs/troubleshooting/) 检查 |

需要合上电脑后仍接收掉线通知，继续配置 [远端值守](/docs/watch/)。Desktop 升级不会自动升级远端 ncd-watch，要在组件页单独更新。
