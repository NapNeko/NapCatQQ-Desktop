Bot 登录 QQ 后，已经可以收发消息。想让它运行插件、处理指令或进行 AI 对话，还要接上一个应用端。NapCat / SnowLuma 是协议端，Karin、NoneBot2、AstrBot 等是应用端；两个进程都正常，对接才算完成。

这篇先完成「安装一个实例 → 配置 → 对接 QQ → 测试」这条路线。各框架的详细配置见 [应用框架](/docs/frameworks/)。

## 开始前

- 已按 [第一个 Bot](/docs/first-bot/) 创建 Bot，并确认 QQ 已登录。
- 确定应用端装在本机还是远端。远端需要先 [添加 SSH 主机](/docs/remote-linux/)。
- 第一次使用时，建议把 Bot 和应用端放在同一台主机。先连通，再调整部署位置。

## 1. 新建应用实例

1. 打开侧栏「组件」，先选主机，再找到准备安装的框架卡片，点击「新建实例」。从「应用端」列表也可以通过「去组件页安装」进入组件管理。
2. 在「安装位置」选「本机」或已经添加的远端主机。从组件页进入时，安装位置固定为当前主机。
3. 填「实例名」，例如 `测试用 AstrBot`。名字用于识别，不是 QQ 昵称。
4. 「监听端口」第一次可以留空，Desktop 会分配高位端口，并避开同机已有实例。手动填写时，范围为 `1–65535`，同机多个服务不能占用同一监听地址和端口。
5. 检查「安装目录」。保留自动路径即可；自选目录时，为每个实例使用独立目录。Linux 远端使用 `/` 开头的绝对路径。
6. 按框架提供的选项选择版本、WebUI 账号或渲染器。出现上游使用条款时，阅读后再继续。
7. 提交创建并安装。打开「任务」查看下载、依赖安装和部署步骤，等待任务结束。

![新建应用实例：先确定主机，再检查端口与安装目录](/docs/screenshots/app-install-light.png)

完成后，「应用端」列表应出现实例卡片，不再是「未安装」或安装中。只创建档案而没有安装的实例，需要先点卡片上的「安装」。

同一框架可以建立多个实例，但每个实例有自己的目录、依赖和配置。「随桌面端启动」按实例设置，新建时默认关闭。

## 2. 配置并启动

1. 点击实例卡片，进入详情。
2. 根据框架填写必要配置。普通插件框架先检查连接、主人或权限；AI 框架先配置模型提供商、模型及所需密钥。具体步骤见 [七种框架](/docs/frameworks/)。
3. 保存配置，留意保存结果。如果提示文件不支持热加载，重启实例后才生效。
4. 启动实例，打开「日志」，确认没有端口占用、依赖缺失或配置解析错误。
5. 框架提供 WebUI 时，可从卡片打开浏览器面板，核对账号及服务状态。

![应用端列表：卡片下方集中放置启停、对接、WebUI 和日志入口](/docs/screenshots/apps-light.png)

部分模型、会话、插件或统计页面要在实例运行后才能读取。页面提示 Dashboard 不可达时，先检查实例进程和日志；旧版框架缺少接口时，按提示升级，或从上游面板操作。

## 3. 一键对接协议 Bot

1. 在实例卡片或详情中点击「对接」。也可从 Bot 配置页进入同一个「对接应用端」对话框。
2. 检查「协议 Bot」和「应用实例」，避免把测试实例接到正在使用的其他账号。
3. 等待生成对接计划，阅读连接方向、地址和主机组合。
4. 确认并应用计划。Desktop 会同时写入两端配置；已有绑定时，界面会说明改绑对象。
5. 启动应用端和 Bot。必要时按提示重启，让新连接生效。
6. 在应用端日志或上游面板查看适配器连接，再用自己的测试账号发送一条已配置的指令。AI 框架则按它的会话规则测试一次回复。

![对接前核对 Bot、应用实例和连接计划](/docs/screenshots/app-link-light.png)

图中的端口、路径和 Token 是演示数据；实际填写和生效范围以你这次生成的对接计划为准。

**成功的判断是双方建立了连接，并且测试消息得到预期处理。** 只看到两个进程都在运行，还不足以说明 OneBot 已连通。

同机可直连，受支持的跨机组合会使用 SSH 隧道。Docker 部署的 Bot 暂不支持应用端一键对接，选项会置灰。手动配置请看 [OneBot 连接](/docs/connections/)；另一台机器上的 `127.0.0.1` 指向它自己。

不再需要绑定时，从卡片使用「解除对接」。这会回退两边的对接配置。更换 Bot 使用改绑入口，先核对计划再应用。

## 导入已经装好的项目

导入是原地接管，项目不会复制到新目录，也不会改变入口。开始前先备份项目，停止你原先用终端、脚本或服务启动的同一实例，避免重复占用端口。

1. 在「应用端」选择「导入已有项目」。
2. 选择正确的「框架」与「主机」。
3. 在「项目目录」选择框架项目根目录，远端填写绝对路径。例如应选择含项目配置的目录，而不是它的上一级。
4. 点击检查项目的入口，阅读识别结果和警告。目录、主机或框架一旦改动，需要重新检查。
5. 核对自动识别的实例名与状态，再确认导入。
6. 进入实例详情，检查配置、连接和日志，随后由 Desktop 启动。

如果检查失败，先确认目录、访问权限和框架是否匹配。不要为了通过检查而随意新建空配置文件；这可能掩盖选错目录的问题。

## 表单、原始文件和保存冲突

常用设置优先用表单。未在表单出现的自定义字段，可从详情的「原始文件」查看和编辑。选择文件后再修改，保存时保留对应格式：JSON、YAML、TOML 或 dotenv。

保存时出现冲突，通常是上游 WebUI、另一个编辑器或框架进程同时修改了文件。先保留自己的改动，再重新读取并核对差异；确认后合并，不要直接把另一侧的新配置覆盖掉。Bot 侧的对接文件在原始文件页只读显示，需要改连接时回到 Bot 配置或对接入口。

## 更新、删除和释放接管

支持版本管理的实例可在详情中查看版本和相应安装操作。更新前先 [导出配置并备份程序数据](/docs/backup/)，停止实例，按页面提示操作；配置包不会替你保存插件程序或数据库。

删除前先看确认框：

- Desktop 新建的实例使用「删除实例」。是否删除安装目录，以确认框中的「同时删除安装目录」为准。
- 导入的实例默认是「释放接管」，会还原导入时的配置和 systemd 设置（如有），注销 Desktop 记录；已绑定的 Bot 连接也会移除。
- 导入实例若勾选「同时删除安装目录」，会删除原项目，快照也无法再还原。

## 启动了，但没有回复

按顺序看四处：安装任务是否成功、应用端日志是否报错、Bot 是否登录、双方 OneBot 是否连接。模型鉴权失败、插件没有启用、会话名单不允许该群，也都可能表现为「没回复」。不要同时修改端口、模型和插件；每次只改一项，再测试同一条消息。
