「机器人」按 QQ 账号管理协议端实例。第一次创建的完整流程见 [创建第一个 Bot](/docs/first-bot/)；这页介绍日常启停、配置和维护。

## 看懂卡片上的状态

![机器人列表：每个账号有独立的运行位置、进程状态和登录状态](/docs/screenshots/bots-light.png)

| 信息 | 用来判断什么 |
| --- | --- |
| 实例名称与 QQ 号 | 你正在操作哪个账号 |
| 底座、运行位置 | 是 NapCat 还是 SnowLuma，在本机、哪台远端或 Docker 中运行 |
| 进程状态 | 已停止、启动中、运行中，或出现退出和修复问题 |
| QQ 登录状态 | QQ 已登录、QQ 未登录、待扫码、探测登录等 |
| WebUI 告警 | 页面是否可达、鉴权是否失败、是否受限或需要两步验证 |
| 待重启等提示 | 保存的设置是否仍需通过重启生效 |

**运行中 + QQ 已登录** 才是账号侧完成登录的状态。若已经运行却一直「探测登录」，先查看 WebUI 与日志，不要直接断定 QQ 离线。远端主机不可达时，还要区分 SSH 连接状态和远端程序是否仍在运行。

## 启动、扫码、停止

1. 启动前核对卡片的 QQ 号、底座和主机。
2. 点击启动，等待启动中的操作完成；不要连续重复启动。
3. 卡片提示扫码时，使用扫码入口或协议端 WebUI / QQ 登录入口完成确认。
4. 正常运行时，按需要打开 WebUI、日志或更多工具。
5. 需要停止时点击「停止 Bot」，等进程状态稳定后再改底座、更新组件或移动数据。

SnowLuma 远端的 WebUI 和 noVNC 依赖对应服务与 SSH 隧道。入口未就绪时先看卡片提示，具体扫码和恢复步骤见 [远端登录](/docs/remote-login/)。

图标按钮可能只显示图标，把鼠标移到按钮上可看提示，例如「查看日志」「配置参数」「更多工具」。不确定时先读提示再点击。

## 修改已有 Bot

从卡片打开「配置参数」。配置页分为「身份」「连接」「高级」。

1. 修改需要的字段。
2. 查看底部「未保存」状态；点击「保存」或使用 `Ctrl+S`。
3. 阅读保存后的提示，确认改动是已生效还是需要重启。
4. 保存后保持 QQ 登录、OneBot 连接和应用端状态可用。

「撤销」用于丢弃当前表单尚未保存的修改，不能撤回已经保存并应用的配置。运行中不能直接切换底座，先停止 Bot。QQ 账号在编辑模式下锁定；要使用另一个账号，应新增对应 Bot。

### 出现「配置冲突解决」时

如果你也在协议端 WebUI 或文件里改过配置，启动或保存时可能发现运行时文件与 Desktop 不一致。先逐项比较两侧值：想采用 Desktop 表单就选桌面端，想接纳文件中的改动就选运行时。运行时新增字段还可以单独决定保留或移除。

确认所有差异的来源后再继续；「全部选桌面端」「全部选运行时」会批量作出同一种选择。拿不准时可以取消，先备份并核对，不要为了关掉弹窗而随意覆盖。远端 OneBot 连接也可先用「从远端读取」同步，见 [连接配置](/docs/connections/)。

### 身份：账号、主机和自愈

| 设置 | 什么时候用 |
| --- | --- |
| 实例名称 | 给账号起容易辨认的本地名称 |
| NapCat / SnowLuma | 选择协议端；NapCat 以后台托管为主，SnowLuma 保留 QQ GUI |
| 本机 / 远程主机 | 选择真正运行 QQ 与协议端的机器 |
| 直接运行 / Docker | 远端 Linux 可选择；Windows 本机固定直接运行 |
| 掉线自动重启 | 进程异常退出或掉线时尝试重新拉起 |
| 定时自动重启 | 按间隔或 Cron 计划重启 |
| 音乐签名接口 | 发送音乐卡片确实需要时，填写可用接口；否则留空 |

切换运行位置会影响程序、路径和网络。先在目标主机准备组件并测试远端连接，不要只把主机下拉框改完就认为数据已迁移。

### 设置一条定时重启计划

1. 打开「身份 → 自愈与附加服务」。
2. 开启「定时自动重启」。
3. 选择「每隔」「每天」「每周」「每月」或「自定义 cron」。
4. 例如每天凌晨维护，选「每天」，在时间选择器设定合适的时刻；先查看页面显示的「下次」执行时间。
5. 保存配置，再确认计划提示符合预期。

自定义 Cron 使用页面提示的 **分、时、日、月、周** 形式，按本地时区预览。优先使用结构化选择器，不要把其他系统的带秒表达式直接复制过来。每月选择 29、30、31 日时，短月份没有对应日期会跳过。

掉线自动重启与定时重启处理的原因不同。遇到持续崩溃或登录异常，先修复原始错误；自动重启不能替你完成 QQ 的安全验证。Desktop 退出后的远端值守需求见 [ncd-watch](/docs/watch/)。

### SnowLuma：冷启动与热启动

- **冷启动（默认）**：由 Desktop 拉起并托管 QQ 进程。
- **热启动**：附加到已经登录这个 QQ 号的 QQ 进程。

第一次使用先按默认方式跑通。选择热启动时，先确保目标机器确实存在对应账号的已登录 QQ，不能靠填写一个 QQ 号去附加任意进程。远端 Windows 还需要可用的桌面会话，见 [远端 Windows](/docs/remote-windows/)。

### 连接：与应用端收发消息

HTTP、SSE、Webhook、正向和反向 WebSocket 都在这里配置。每条连接有自己的名称、启用开关和 Token。先「保存连接」，再保存 Bot 配置；方向、端口与验证方法见 [连接应用端与 OneBot](/docs/connections/)。

已保存的 Bot 可以从此处「对接应用端」。远端 WebUI 里改过连接时，用「从远端读取」核对差异再保存，避免下次启动被 Desktop 的旧配置覆盖。

### 高级：启动、通知与协议端选项

「随桌面端自动启动」表示打开 Desktop 时拉起这个 Bot，不等于让 Windows 自动启动 Desktop。若希望开机后运行，还要分别检查 Desktop 自身的启动设置和账号登录条件。

「掉线时发送通知」还需要在「设置 → 通知」启用、配置并测试推送通道。SnowLuma 的该项可以即时生效，NapCat 按界面提示重启后生效。测试方法见 [设置](/docs/settings/)；远端独立通知见 [ncd-watch](/docs/watch/)。

NapCat 的高级页还包括：

- **本地文件到 URL、合并消息上报解析**：按下游应用需求调整消息行为。
- **文件日志、控制台日志与等级**：选择要保留的日志和详细程度，修改核心日志配置后需重启 Bot。排错结束后可以调回常用等级。
- **封包后端、封包服务地址与反检测选项**：先保持默认；只有协议端说明或明确错误要求时再改，并记录修改前的值。全部开启并不能保证兼容或稳定。

SnowLuma 的高级页还提供全局 WebUI / 简化扫码相关设置，以及 `#sl` 状态命令：

- 「启用 #sl 状态命令」决定是否响应群聊或私聊中的状态探测。
- 「命中后不转发给下游（swallow）」决定状态命令是否继续投递给应用端。
- 「回复冷却（秒）」限制同一会话的触发频率，`0` 表示不限制。
- 带「全局」的扫码或 WebUI 设置可能影响多个 SnowLuma 账号，修改前看清适用范围。

## 查看日志与运行时指标

### 用日志定位失败阶段

1. 在卡片点击「查看日志」。
2. 找到与你刚才操作时间相近的记录。
3. 先看第一条明确错误，再看它前后的上下文。
4. 记录协议端版本、运行方式与错误；提交问题前隐藏 Token 和私人消息。

![Bot 运行日志：保留失败前后的上下文](/docs/screenshots/bot-logs-light.png)

安装失败看「任务」，应用插件报错看应用实例日志，Desktop 自己的异常看桌面日志。不要只提供一张没有时间和上下文的错误提示。日志操作见 [任务与日志](/docs/tasks-logs/)。

### 启用并查看指标

1. 到「设置 → 监控」打开实例指标并保存。
2. 按提示重新启动 Bot，让探针载入。远端还需要同步 ncd-watch；升级前已运行的原生 SnowLuma，可能要先停止同机所有账号再启动。
3. 从 Bot 卡片的更多工具打开「运行时指标」。
4. 观察当前总览、系统资源与节点流量，再切换历史趋势的时间范围。
5. 排查某段波动时，用时间范围面板选择开始与结束时间；需要持续观察时可跟随当前时刻。

探针未载入或读取失败会显示提示，不要把缺失数据理解为占用为零。本机历史由 Desktop 在线时采样；远端历史由同机 ncd-watch 续写。历史可选范围受设置中的保留天数约束，详见 [设置](/docs/settings/) 与 [ncd-watch](/docs/watch/)。

## 多个 Bot 的整理和批量操作

列表可通过卡片拖动手动排序。需要一次处理多个账号时：

1. 点击右下角「批量管理」。
2. 逐个勾选目标卡片，核对选中数量、QQ 号和所在主机。
3. 在底部批量栏选择启动或停止。
4. 等待各实例状态刷新；部分失败时逐个看日志与主机连接。

批量启动不会绕过缺少组件、QQ 登录或远端权限的要求。实例较多时，先启动一个确认正常，再逐步恢复其他实例。

## 导入远端已有 Bot

如果服务器上已经有 NapCat / SnowLuma 安装或 Docker 容器，可以登记到 Desktop：

1. 在「远端」添加对应 SSH 主机，测试连接并刷新库存。
2. 回「机器人」，点击右下角「导入已有 Bot」。
3. 在列表中核对协议端、主机、部署方式和 QQ 号，选择需要接管的项目。
4. 未发现时点击「重新发现」，仍失败则回到远端检查权限和安装位置。
5. 确认导入，再检查导入结果和各 Bot 的连接配置。网络配置迁移失败可能不阻止档案导入，要按结果提示继续处理。

导入默认不改写远端 WebUI 密码。只有确认需要时才勾选「接管 WebUI 密码」；该选项影响所选远端原生 SnowLuma 下次启动时的密码覆盖。已有运行实例导入后会尝试接入控制台，若接管运行态失败，先保留错误再检查，不要立即重复新建同号 Bot。

## 删除 Bot

单个配置页和批量管理都提供删除入口。确认对话框会说明删除范围；运行中的进程会先停止，配置与相应数据项会被永久删除，无法通过「撤销」恢复。

临时不用时优先停止。确实要删除时，先导出需要的配置，并按 [备份与数据](/docs/backup/) 另外保存程序、数据库或消息等不在配置包内的内容，再核对 QQ 号后确认。
