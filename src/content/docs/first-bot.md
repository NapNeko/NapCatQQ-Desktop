下面是在自己的电脑上操作的步骤，使用 **Windows 本机 + NapCat + 直接运行**。演示中已就绪的组件，在实际使用前仍需检查或安装；插件回复在连接应用端后配置。

实际登录需要能用手机 QQ 扫码确认的账号。配置里填写数字 QQ 号，不是昵称、手机号或密码。

## 1. 准备本机组件

1. 打开侧栏「组件」。
2. 在主机选择区确认选中的是 **本机**。
3. 查看 QQ 的状态。需要安装时点击「安装」，等待任务完成。
4. 找到 NapCat，点击「安装」，按任务提示完成运行时和协议端准备。
5. 等待组件状态重新检测，确认相关项目已经可用。

![组件页：先选择本机，再准备 QQ 和 NapCat](/docs/screenshots/components-light.png)

安装期间可以到「任务」看下载与安装进度。不要在显示下载中时连续点击安装；失败时先展开失败步骤，保留错误内容，再按提示重试。下载慢见 [网络设置](/docs/network/)，组件状态说明见 [组件管理](/docs/components/)。

**关于系统 QQ：** Desktop 管理的 QQ 程序与日常系统 QQ 分开放置。若探测到并准备使用系统 QQ，请认真看启动前的说明；也可以在 QQ 组件卡上选择「转为 NCD 管理」，单独安装一份供 Bot 使用。程序文件分开不表示 QQ 的登录数据完全隔离。

## 2. 新增 Bot 配置

1. 打开「机器人」。
2. 点击右下角带加号的 **新增 Bot**。
3. 在「身份」页填写下表。

| 项目 | 这次填写什么 | 为什么 |
| --- | --- | --- |
| QQ 账号 | 你准备登录的数字 QQ 号 | Desktop 用它标识账号，创建后不能在原配置中直接改号 |
| 实例名称 | 例如 `我的第一个 Bot` | 便于在多张卡片中辨认，不影响 QQ 昵称 |
| 底座类型 | NapCat | 本教程选择后台运行的协议端 |
| 运行宿主 | 本机 | 在当前 Windows 电脑运行 |
| 启动方式 | 本机固定直接运行 | 本机不支持 Docker |

![新增 Bot：填写 QQ 账号和实例名称，选择 NapCat 与本机](/docs/screenshots/bot-create-light.png)

先保持「掉线自动重启」「定时自动重启」关闭，便于第一次排查启动结果。音乐签名接口只在需要发送音乐卡片时使用，本次留空即可。「高级」中的日志、封包后端等设置也先保持默认。

4. 点击配置页右上角的「保存」。
5. 确认页面不再提示「未保存」，返回机器人列表。

**完成标志：** 列表中出现你刚命名的卡片，QQ 号和本机位置正确。仅创建配置还没有启动程序，卡片此时可以显示未运行。

## 3. 启动并完成 QQ 登录

1. 在这张 Bot 卡片上点击启动入口。
2. 等待协议端启动。若提示组件缺失，回到「组件」处理缺少的项目。
3. 打开该 Bot 提供的 **WebUI**，按 NapCat 页面提示查看二维码或登录状态。
4. 用对应账号的手机 QQ 扫码，并在手机上确认登录。
5. 回到 Desktop，观察 Bot 卡片的进程和登录状态。

二维码过期就刷新后再扫；手机要求设备验证时，先按 QQ 的提示完成。不要把二维码、WebUI 访问地址中的密钥或密码发到公开聊天里。

如果选的是 SnowLuma，启动后还会保留 QQ 图形界面，登录入口与 NapCat 不同。需要 SnowLuma 的简化扫码、远端 noVNC 或启动模式说明，见 [远端登录](/docs/remote-login/) 与 [机器人管理](/docs/bots/)。

## 4. 确认登录成功

启动完成后检查两件事：

- **进程状态：** 协议端确实在运行，没有启动后立即退出。
- **QQ 登录状态：** 账号已登录，而不是仍在等待扫码或离线。

![机器人列表：分别检查运行状态与 QQ 登录状态](/docs/screenshots/bots-light.png)

卡片的运行状态与 QQ 在线状态是两个信息。程序运行中不代表 QQ 已登录；同样，QQ 登录成功也不代表应用端已经连接。

还不确定时，打开卡片的「日志」，查看最新的启动、登录或错误信息。不要只看最后一行：失败原因可能在进程退出前几行。

![Bot 日志：确认启动过程，定位登录前后的错误](/docs/screenshots/bot-logs-light.png)

## 5. 做一次停止与重启

确认登录后，点击卡片的停止入口，等状态变成已停止，再重新启动一次。这能帮助你确认组件和配置已经保存。是否需要重新扫码取决于 QQ 的登录状态；Desktop 不保证每次重启都能免扫码。

接下来先保持 Bot 在线，继续 [连接应用端与 OneBot](/docs/connections/)。你可以先通过 HTTP 查询自己的登录信息，再安装一个应用端。

## 如果没有走到成功状态

| 现象 | 先做什么 |
| --- | --- |
| 保存时报账号或实例名称错误 | QQ 号填正整数，名称不要留空；远程模式还必须选择具体主机 |
| 提示组件缺失 | 回到「组件 → 本机」，查看 QQ、协议端和所需运行时 |
| 下载或安装失败 | 打开「任务」定位失败步骤，不要先删除全部目录 |
| 启动后立即停止 | 打开 Bot 日志，记录退出前错误、协议端版本和 QQ 版本 |
| WebUI 打不开或要求鉴权 | 使用 Bot 卡片提供的入口，检查启动日志和界面提示，不要随意改成另一个端口 |
| 一直等待登录 | 检查二维码是否过期、手机是否确认、QQ 是否要求额外验证 |
| 已在线但不回复 | 登录阶段已经完成；继续配置应用端、插件与 OneBot 连接 |

更完整的排查顺序见 [故障排查](/docs/troubleshooting/)。
