SnowLuma 的简化扫码会从 QQ 原来的登录界面获取二维码，显示在 Desktop 里。你仍用手机 QQ 扫码并确认，不需要把远端整个桌面一直打开。

## 1. 检查这台主机是否具备扫码条件

| 运行方式 | 获取二维码依赖 | 不能取码时用什么 |
| --- | --- | --- |
| Windows 原生 | UIA 登录控件定位、单窗口捕获；QQ 与扫码辅助在可用桌面会话 | QQ 原窗口 |
| Linux SSH 原生 | Python 3、AT-SPI、X11、可用的会话 D-Bus | VNC / QQ 图形窗口 |
| 官方 SnowLuma Docker | 容器内同用户、同显示环境的无障碍与窗口捕获环境 | VNC |

自定义 Docker 镜像保留 VNC 登录方式，不能假定具备官方镜像的扫码辅助环境。真实 Docker 手机扫码和消息收发仍需在你的部署上确认。

简化扫码默认开启。以前的配置如果明确关闭过，会保留关闭状态。在 Bot「配置 → 高级」中，可以调整「Windows 简化扫码（全局）」或「简化扫码登录（全局）」。这是对应运行环境的全局设置，修改会影响该类 Bot。

## 2. 启动 Bot，再打开扫码窗口

1. 在 Bot 配置里核对 SnowLuma 底座和运行主机，保存。
2. 启动 Bot，等 QQ 和 SnowLuma 完成启动。
3. 点击 Bot 卡片上的「扫码登录」。仅在你打开扫码窗口时，Desktop 才开始取图。
4. 首次打开时，辅助会从 QQ 的账号选择或快捷登录页切到原来的扫码页，不会自动提交快捷登录。
5. 用要登录的那个 QQ 的手机端扫描二维码，并在手机上确认。

扫码后不要连续点击刷新。界面已识别扫码时会停止取图、禁用刷新，等待手机确认。登录成功后二维码会被清空，扫码辅助停止。

QQ 主界面已经出现，但 SnowLuma 尚未确认账号时，会显示「等待 SL 确认」。此时先等协议端状态，不会继续截取 QQ 主界面。

## 3. 二维码过期或手机取消后怎么继续

- 二维码过期：在扫码窗口中手动刷新，再用手机扫描新的码。
- 手机取消登录，想重新扫码：关闭扫码窗口后重新打开。
- 已经扫码，仍在等待：先检查手机是否还需要确认，不要试图强制刷新已扫码的二维码。
- 报告辅助清理异常：查看提示，用 QQ 原窗口或 VNC 完成登录；请求有超时，但无法确认辅助完全退出时会明确提示。

关闭窗口、切换 Bot、隐藏扫码页面、关闭这项功能或停止 Bot，都将取消取图请求并清空图片。

## 改了开关，为什么当前 QQ 没变化

开关默认值和设置变更在**下次冷启动 QQ**时准备环境，不会自动重启已经运行的 QQ 或容器。

在合适的时间停止对应 Bot，再由 Desktop 启动。Linux 已运行的 QQ 如果已有可用无障碍会话，可在打开扫码时按需绑定；会话 D-Bus 失效时仍需要重新启动 Bot。

Docker 也只在冷启动受支持镜像时准备环境，不会为了取码自动重建运行中的容器。扫码成功或取消不会删除 QQ 的正常启动包装和挂载目录。

## 无法取码，按顺序检查

1. **Windows 远端：**目标用户是否登录了桌面，桌面是否解锁，是否存在多个会话？按 [Windows 管理](/docs/remote-windows/) 先让工作进程就绪。
2. **Linux：**是否使用 X11，Python 3、AT-SPI 与会话 D-Bus 是否可用？Wayland 或缺少依赖时，直接使用回退入口。
3. **QQ 窗口：**是否最小化、被遮挡，或登录布局不兼容？恢复窗口后再试，仍不行就使用原窗口 / VNC。
4. **刚开启功能：**是否重启过对应 QQ？开启开关不会临时联网安装缺失依赖，也不会替你重启 QQ。

二维码只通过私有通道保存在内存，不写文件、日志或浏览器缓存，也不为取码新增公网端口。不要把二维码贴到公开 Issue；它仍属于一次有效登录凭据。

需要在离线后由另一个 Bot 发送重登二维码，继续看 [值守中的同机互助](/docs/watch/#启用同机互助重登二维码)。这项功能还需要 ncd-watch、管理员和互助连接，单独打开简化扫码并不会自动发通知。
