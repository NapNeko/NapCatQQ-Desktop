这页接着[安装并对接应用端](/docs/apps/)往下走。先找到你安装的框架，把一条消息跑通，再增加插件、模型和规则。同一框架的多个实例各有配置和目录，修改前先看详情页顶部的实例名与主机。

## 先弄清楚保存在哪里

- 配置表单出现「有改动还没保存」时，点底部「保存」，或在表单中按 `Ctrl+S`。有错误时点「去看看」定位；点「撤销」会丢弃本次草稿。
- 人格、知识库、学习记录等运行数据，由框架自己的服务提供。有些对话框点「创建」「保存」就立即写入，不需要再找底部保存条。
- 页面提示「实例没在运行」时先启动；提示控制台登录失败时，核对这一个实例的 WebUI 凭据。QQ 已登录不代表框架控制台也已登录。
- 看到重启提示就按提示重启。原始文件入口适合保留自定义字段；同时在 WebUI 和 Desktop 修改同一份配置时，先处理保存冲突，再继续。

![应用端配置表单](/docs/screenshots/app-config-light.png)

截图使用浏览器演示数据，展示界面和操作位置；模型调用、插件下载与 QQ 回复仍需在你的实例中验证。

## Karin：装一个插件，限定响应范围

### 准备连接与主人

1. 打开「应用端」，进入 Karin 实例详情。按[对接步骤](/docs/apps/)关联协议 Bot。
2. 进「权限」，在「主人」填你自己的 QQ 号，需要协助管理时再填「管理员」。不要把 Bot 自己的 QQ 号当成主人号。
3. 检查「用户名单」和「事件范围」。白名单不为空时会限制范围；事件开关关闭后，对应类型不会交给插件处理。
4. 保存，启动 Karin 和 Bot。先用主人账号，在你允许的会话里测试。

完成后，双方日志应能看到连接建立。普通指令是否回复还取决于有没有安装对应插件。

![Karin 权限页：先填主人，再检查名单与事件范围](/docs/screenshots/framework-karin-light.png)

### 安装与管理插件

1. 进「插件」，输入插件名搜索。可以按 `npm`、`git`、`app` 类型筛选。
2. 找到目标后点安装，等待任务结束。首次使用先选一个文档齐全、依赖少的插件。
3. 已安装插件通过「插件操作」菜单启用、禁用、更新或卸载。有配置入口的插件，打开配置，填写它自己的必填项后保存。
4. 按插件说明发送一条实际指令。没有回复时先看插件有没有启用，再看实例日志是否报告依赖或配置错误。

只是不想继续响应某个插件时，先禁用比较容易恢复；卸载前备份插件自己的数据。

### 调整规则、日志与渲染

「响应规则」分「群 / 频道」和「私聊」。先确认要修改的是默认规则还是具体目标，再填写目标和对应规则；改完在同一个会话测试，避免用另一条规则下的会话验证。

「基础」管理运行器、`NODE_ENV`、日志等级、保留天数、单文件上限和 FFmpeg 路径。已有实例能正常运行时，不必为了装插件改运行器。FFmpeg 路径留空会从 `PATH` 查找。

「渲染与存储」可配置渲染器 WS / HTTP 的地址、Token，以及 Redis。图片插件报渲染连接失败时，检查这里指向的渲染服务是否已启动。Redis 修改需要重启；不要把 Redis 密码填进渲染器 Token。

## NoneBot2：适配器、插件与命令前缀

### 把 QQ 接进来

1. 进入 NoneBot2 详情的「适配器」，搜索并安装与你的 OneBot v11 连接匹配的适配器。NapCat / SnowLuma 的连接不能用其他平台适配器代替。
2. 进「连接」，检查 `HOST`、`PORT` 与 `ONEBOT_ACCESS_TOKEN`。使用一键对接时先通过对接入口生成配置，再回来核对。
3. 在 `SUPERUSERS` 填自己的 QQ 号；`NICKNAME` 填 Bot 可识别的称呼。
4. 保存并启动。观察日志中是否成功载入适配器、是否有 Bot 连接记录。

已对接实例修改端口或 Token 会重写对接。跨机器地址、正反向 WS 的区别见 [OneBot 连接](/docs/connections/)。

![NoneBot2 连接页：HOST、PORT、Token、主人和命令前缀在同一页检查](/docs/screenshots/framework-nonebot2-light.png)

### 安装一个插件并验证

1. 打开「插件」，搜索目标，阅读其说明与适配器要求后安装。
2. 对需要配置的插件，打开配置入口，补齐 API Key、目标群等插件要求的项目。
3. 回到「连接」查看「命令前缀」。例如前缀里有 `/`，插件命令为 `help`，通常应按插件说明发送 `/help`；插件可能自定义匹配规则，仍以插件文档为准。
4. 保存，需要时重启实例。先在一个允许的会话中测试，再给更多群使用。

「无前缀也响应」会把空前缀加入配置，可能让普通聊天触发插件。先保持关闭；确定插件匹配范围后再开启。「命令分隔」与「自定义键」用于插件或项目要求的设置，不知道用途的键可以先保留原值。

安装成功但插件加载失败时，查看实例启动日志。目录中有包不代表插件已经成功导入；缺少 Python 依赖、适配器不匹配和插件本身错误，需要分别处理。

## AstrBot：先选模型，再决定怎么回复

### 添加提供商与默认模型

1. 进入「模型」，点「添加提供商」，选择与你服务商相符的类型或预设。
2. 在对话框填自己的「API Key」与服务商给出的「接口地址」。确认提供商已启用，在名下加入服务商实际支持的模型标识，并启用模型。
3. 确认对话框后，保存页面配置。新提供商尚未保存时，服务端还不认识它，不能直接拉取其模型列表。
4. 回到页面顶部「默认模型」选择刚加入的对话模型。需要容错时，再选择「备用模型」并排好顺序；默认模型出错后会按顺序尝试。
5. 保存，启动或按页面提示重启实例。

默认模型下拉没有选项时，检查提供商和模型两层是否都启用，以及提供商类型是否用于对话。接口地址、API Key 与模型 ID 都以同一家服务商的说明为准，不要把展示名称当模型 ID。

![AstrBot 模型页：先配置提供商及模型，再选择默认与备用模型](/docs/screenshots/framework-astrbot-light.png)

### 给它一个人格并接收测试消息

1. 进入「连接与账号」，核对 OneBot v11 连接与 WebUI 凭据；完成与协议 Bot 的对接。
2. 启动 AstrBot，等控制台连接成功，再进入「人格」点「新建人格」。填写唯一「标识」，例如 `helper`，再写系统提示词，例如「回答先给步骤；不确定时说明缺少什么信息」。
3. 在人格列表点「设为默认人格」，再保存页面配置。人格内容由控制台即时保存；选择默认人格另需保存配置。
4. 进入「回复设置」，开启「大模型回复」。检查「唤醒前缀」「对话额外前缀」「私聊也要唤醒前缀」和白名单，保证测试会话满足这些条件。
5. 在允许的 QQ 会话按设定前缀发送一句测试消息。成功时应收到回复，日志中没有鉴权或模型调用错误。

群成员需要各自上下文时使用「独立会话」。要限制消耗，可在「上下文与工具」设置保留轮数、工具调用步数和超时；语音与联网搜索需要对应提供商，开启开关本身不会补齐服务。

### 知识库、会话规则与子代理

| 想做什么 | 操作与边界 |
| --- | --- |
| 新建知识库 | 实例运行且控制台连通后，进「知识库」创建名称、说明与向量嵌入提供商。创建后不能更换该嵌入提供商。文档上传和切片在 AstrBot WebUI 完成。 |
| 对话使用知识库 | 在同页打开目标知识库的「挂到对话」，配置召回与最终保留条数后保存。建了知识库不代表已挂到对话。 |
| 给某个会话换设置 | 在「会话规则」按会话增加规则，例如单独更换模型或关闭大模型。核对会话目标后提交。 |
| 创建配置档案 | Desktop 可建、删档案；其它档案的内容和会话绑定在 WebUI 管理，Desktop 表单编辑默认档案。 |
| 编排子代理 | 先在「模型」「人格」准备好，再在「子代理」组合模型与人格，设置路由提示词和工具，保存后测试路由效果。 |
| 扩展能力 | 「插件」中安装、配置并启用所需插件，再看日志确认加载。 |

删除知识库会连同文档与向量一起删除；删除档案会让其绑定会话回到默认档案。操作前先核对目标并做好框架数据备份。

## MaiBot（麦麦）：模型、名单和试聊

### 配好提供商、模型和任务

1. 进入「模型」，在「提供商」点「加提供商」，选择对应预设，填写「接口地址」和自己的「API Key」。默认占位 Key 必须替换。
2. 在「模型」中添加条目，给一个便于辨认的「名称」，填写服务商实际的「模型标识」，并选择刚才的提供商。支持看图的模型才开启「能看图」。
3. 在「任务分配」里，至少给「回复」「规划」「杂务」三个任务选模型。只添加模型而不分配任务，麦麦仍不能正常说话。
4. 按需为「识图」选择视觉模型；为「嵌入」选择文本嵌入模型。嵌入任务不能拿普通对话模型代替。
5. 保存。实例运行且 WebUI 应答后，可使用提供商测试、模型列表拉取等入口核对服务。

「高级选项」里有鉴权、重试、超时、温度、最大输出和计价。先用服务商支持的默认值；输入输出价格只用于统计花费，并不会修改服务商账单。删除仍被任务引用的模型会标红，先把任务改到有效模型再保存。

![麦麦模型页：提供商、模型与任务分配需要逐层配置](/docs/screenshots/framework-maibot-light.png)

### 放行一个测试会话

1. 在「连接」确认已对接协议 Bot，并核对 WebUI 端口。旧版消息服务端口即使适配器插件用不上，也必须空闲，否则麦麦可能无法启动。
2. 打开「聊天名单」，检查「按名单过滤」、群聊和私聊的名单模式。
3. 默认空白名单不会放行任何消息。第一次测试只添加你自己的 QQ 或一个测试群，避免一下子接收大量群消息。
4. 检查「屏蔽用户」，确认测试账号不在其中。保存，启动麦麦与协议 Bot。
5. 回「概览」查看对接、模型、名单和运行状态提示，再去 QQ 测试。

### 先试聊，再调人格与提示词

「试聊」直接走麦麦 WebUI 的聊天室，不经过 QQ，适合分开判断模型链路与 OneBot 链路。

1. 麦麦运行并连接 WebUI 后，进入「试聊」，填希望麦麦称呼你的昵称。
2. 发一句简单问题。`Enter` 发送，`Shift+Enter` 换行。图片可选择、粘贴或拖入，一条最多 8 张，单张本机图片预览限制为 3 MB。
3. 能在试聊回复、QQ 不回复时，优先检查协议 Bot 对接、聊天名单与会话规则。
4. 在「人格」调整身份和说话方式；需要改模板时进入「提示词」，按语言或关键词查找，改完保存，再用同一个问题比较。

提示词在运行时通过 WebUI 保存，停止时直接编辑文件。刚启动、WebUI 还未就绪时先等待；不要同时从两处改。清空试聊只清这里的对话，麦麦对你的印象和学到的内容仍可能保留。

### 调整一个群的表达学习策略

「表达学习」决定要不要学、要不要使用；「表达方式」展示已经学到的记录。关闭学习不会删除旧记录，也不会自动禁止使用旧记录。

1. 进入「表达学习」，找到「表达方式 → 学习配置」。实例运行且 WebUI 连通后，可点「从聊过的里选」选测试群；没有聊天记录时，点「加一条」，填写该聊天实际的平台、群号和「聊天类型」。
2. 在这条规则中保持「使用」开启，关闭「学习」。这样该群仍可用已有表达，但不再继续从这个群学习新表达。平台与聊天流 ID 都留空会成为默认规则，限定一个群时要填完整目标。
3. 保持「使用精选表达」开启。需要让麦麦用上某条已有表达时，进「表达方式」找到它，点星标精选；只关闭学习不会替你完成精选。
4. 点底部「保存」，再重新进入该页，核对目标群及两个开关仍是刚才的值。若提示需要重启，再按提示处理；学习是后台行为，刚发一句话没有新增记录并不能单独证明配置失败。
5. 「黑话」小节有独立的「学习配置」。若同一个群也要停止学黑话，在这里给同一个目标关闭「学习」，不要以为上面的表达规则会一并控制它。

「优化表达方式学习」会在写入前让 AI 检查内容，可能增加模型调用。「表达使用方式」的「超级精细」需要嵌入模型，先在模型页配置好对应任务；没有该模型时先保留「随手」。需要跨群共享时再配置共享组，逐个核对组内聊天，避免把不同群的语气混在一起。

### 给一个会话追加提示词与时间规则

先用一个已经在「聊天名单」放行的测试群。这里的规则改变回复方式，不会代替聊天名单放行。

1. 进「会话规则 → 按聊天追加的提示词」，在「额外 Prompt」点「从聊过的里选」选中目标。手填时补齐 `platform`、`item_id`、`rule_type` 和 `prompt`；类型选群聊或私聊，与实际目标一致。
2. 在 `prompt` 写一条容易验证的要求，例如「讲解安装问题时，先给一个操作步骤，再等待我确认」。平台、聊天 ID 和提示词必须一起填写，缺项会阻止保存。
3. 保存后，在这个会话提出安装问题，观察回复风格；再去另一个没有这条规则的会话比较。它是给该会话追加的提示，不会替换通用人格，也不保证模型每次逐字遵守。
4. 想在夜间减少发言，进入同页「分时段发言频率」，打开「启用动态发言频率规则」，在「动态发言频率规则」给同一个目标加一条：时间段填 `22:00-08:00`，发言频率可先设为 `0.3`。
5. 保存，核对规则目标和麦麦运行环境的实际时间。频率 `1` 表示正常、较低值更安静，它不是“每几条消息必回一条”的计数器。第一次只添加一条明确规则，确认效果后再扩展时段。

「关键词反应」可以在命中时追加固定提示：新增规则后，关键词和正则至少填一种，并填命中后的反应提示；正则需要按一行一条填写。「消息过滤」用于排除内容。遇到完全不回复时，先核对名单和过滤条件，再检查发言频率，不要同时改多组规则后才测试。

### 接入一个已有的 MCP 服务

先准备一个你已经部署或获准使用、明确支持 MCP 的服务，并取得它的传输方式、地址和鉴权信息。普通网页或模型 API 地址不能直接当作 MCP 服务地址。Desktop 负责配置与试连，不会替你部署服务。

1. 进入「MCP」，打开「启用 MCP」，在「MCP 服务」点「加一条」。填一个唯一「服务名称」，例如 `test-tools`，并打开「启用服务」。
2. 服务文档要求 Streamable HTTP 时，「传输方式」选「远程 HTTP」，「服务 URL」填文档给出的完整地址；要求 SSE 时选「旧版 SSE」。需要 Bearer 认证的，在「远程认证」选择 `Bearer Token`，填实际令牌；其它请求头按服务要求填「请求 Headers」。
3. 若服务要求本地命令，改选「本地命令（stdio）」，按它的安装说明填写「启动命令」「命令参数」「环境变量」。每个参数单独一条。命令必须能在**麦麦所在的主机**运行；远端实例不能直接使用你 Windows 电脑上的程序路径。
4. 启动麦麦并等待 WebUI 连通。此时页顶会出现每个服务的连接状态；点该服务「试连」，用当前草稿检查。成功时会显示“连得上”及工具数量，失败时按提示检查地址、认证、运行依赖或服务本身。
5. 试连通过后仍要点底部「保存」。等待麦麦加载配置，确认持久状态为「已连上 · … 个工具」；如果显示刚保存需要等重载，先等待或按保存结果给出的提示操作。
6. 用一条确实需要其中某个工具的问题验证，再看麦麦日志确认调用。连得上只证明服务连接成功；模型是否选择工具、工具执行是否成功还需要这一步验证。

启用服务必须有唯一名称：stdio 必填启动命令，HTTP / SSE 必填 URL，Bearer 认证必填 Token。页面会把这些缺项标红；点保存条「去看看」定位。尚未配置的空条目可以删掉，或先关闭「启用服务」。

「客户端高级能力」中的 Roots 会向服务声明可访问的目录，Sampling 允许服务请求调用模型；只有确实需要时才配置。界面标为「暂未支持」的 Elicitation、携带上下文等项目先保留关闭。MCP 配置可能包含令牌或环境变量，导出配置包前也要按[备份说明](/docs/backup/)妥善保存。

### 管理学到的内容与长期记忆

| 页面 | 可以怎样用 |
| --- | --- |
| 表情包 | 按收下、认识、不认识、丢弃筛选，查看大图并修改情绪标签。上传一批时先预览，再填写共用标签；无标签的图片不会被按标签挑中。只是不想再发某张图可以丢弃，删除则会删掉图片。 |
| 表达方式 | 按聊天和精选状态筛选，星标精选或批量处理。默认配置下只有精选内容会用于回复。 |
| 黑话 | 查看含义与适用范围，确认、排除、固定或设为全局；错误词条可以编辑，删除后仍可能从后续聊天重新学到。 |
| 人物 | 搜索称呼、昵称或账号，修改麦麦对对方的称呼。删除后再次遇到该用户可能重新认识。 |
| 知识库 | 长期记忆启用并加载成功后，使用「导入 / 浏览 / 图谱」。导入可粘贴文字或选本机文件，填写名称、内容类型和适用聊天，再看进度。开启模型抽取会产生模型用量。 |
| 知识浏览与图谱 | 按来源查实体、关系和事实，删除前检查连带内容；支持的删除可在「最近删除」恢复。图谱支持搜索、拖动和缩放。 |
| 行为 | 查看学到的情境、行为和反馈。此页只读，场景图谱、检索调试等分析入口在麦麦 WebUI。 |

学习记录、知识库和聊天数据属于框架自己的数据库。导出 Desktop 配置 ZIP 不会把这些数据库一起备份，见[备份边界](/docs/backup/)。

## Koishi：插件树、市场与沙盒

### 先把连接跑通

1. 打开 Koishi 详情，完成协议 Bot 对接，再启动实例。
2. 进「服务器」核对端口与监听地址。控制台与 Bot 的反向 WS 共用这个端口；改端口时 Desktop 会同步更新 Bot 对接地址。
3. 跨机器使用 Desktop 对接时会走 SSH 隧道，不必为了对接把监听端口直接暴露到公网。
4. 在「连接」检查当前对接；在「概览」查看控制台给出的 Bot 在线情况。

`selfUrl` 用于有域名、反向代理等场景下生成对外链接，不是随便填一个地址就能让远端访问。接收图片或回调异常时，再结合你的代理和网络配置核对它。

### 装包之后，把插件加进树

1. 打开「插件市场」搜索并安装目标包，等待任务结束。
2. 回到「插件」点「添加插件」，从已安装的包里选中目标。市场装好包和插件树启用配置是两个步骤。
3. 在左侧选中插件，右侧按表单填写必填项，也可切换到配置原文。
4. 打开该节点开关，保存。运行中改配置可能触发 Koishi 重载，Bot 会短暂断开后重新连接。
5. 打开「试聊」发送插件规定的指令，再在真实 QQ 会话验证一次。

插件树可以分组、移动，也可为同一插件再开一份配置，例如第二个适配器账号。Desktop 对接写入的节点会标明用途；界面提示 Koishi 或 Desktop 必需的插件不能停时，保留它。

![Koishi 配置面板：从实例导航进入对应设置，再检查运行和保存状态](/docs/screenshots/framework-koishi-light.png)

「载入条件」即使在节点开关开启时也可能阻止插件加载。需要修改条件时去原始文件，先保存现有配置副本。

### 用原生工具排查

- 「全局设置」管理指令前缀、昵称、国际化和延迟等。运行中保存会重载，短暂断线属于这一步的预期行为。
- 「试聊」是控制台沙盒，不等同于 QQ 账号上线。可调整模拟用户名与对话模式，用来验证插件本身。
- 「指令」可以搜索指令或别名，调整权限等级、冷却和次数上限，再保存。测试时注意账号权限与冷却限制。
- 「数据库」可看表结构和分页记录，目前只读；需要改数据时使用插件或上游控制台。
- 「文件」可浏览实例目录，新建、重命名和删除，文本可编辑、图片可预览，二进制不提供编辑。修改运行配置前先备份，并按框架要求重载。

## TRSS-Yunzai（云崽）：主人权限与群规则

### 配主人并验证指令

1. 在「主人与权限」的「主人 QQ」填你自己的 QQ 号。多个 Bot 需要不同主人时，在「只对某个 Bot 的主人」按 `Bot号:主人号` 填写。
2. 在「连接」完成 OneBot 对接，核对云崽服务端口与 token。HTTP 和 WS 共用该端口，端口变化需要重启。
3. 检查 Redis 配置；本机 Redis 程序可在「组件」页管理。连接失败先查地址、端口、库号和密码。
4. 保存，启动云崽与 Bot，再按已安装插件的说明测试一条普通指令和一条主人权限指令。

普通指令能响应不代表主人权限已配好；`#更新`、`#重启` 等管理指令只认主人。不要靠放开所有用户权限来绕过主人号填错的问题。

![云崽的主人与权限：用自己的 QQ 号设置主人，并核对申请与消息范围](/docs/screenshots/framework-yunzai-light.png)

### 只让一个群使用指定功能

1. 进「群聊」，先看「所有群的默认」中「响应哪些消息」、群冷却、个人冷却和功能名单。
2. 需要只改测试群时，在「单独设置」增加目标群号，填写该群要覆盖的项目。留空项沿用默认。
3. 如果同一个群里有多个 Bot，用 `Bot号:群号` 指定对象；优先级是 `Bot号:群号 → 群号 → Bot号:default → 默认`。
4. 保存，在目标群测试。冷却时间内再次发送可能不响应，等冷却后再试。

「主人与权限」还控制好友申请、群邀请、私聊与黑白名单。白名单非空时只处理名单内目标；开放「谁拉进群都同意」前先确认你确实需要。

### 图片渲染与插件

「渲染」可选自动、shotium 或 puppeteer。自动模式会按模板是否有脚本选择；puppeteer 需要浏览器，安装时没下载 Chrome 的，填写可用的 Chrome / Edge 路径，或配置独立运行的远程浏览器地址。

插件在「插件」页安装、配置、更新或卸载。云崽目录插件整体加载，只有支持的单 JS 插件可单独启停；开关不可用时按提示处理。「基础」还可设置自动更新、自动重启、cron 计划、日志和文件监听；先让实例稳定运行，再添加定时操作。

## NeoBot：先连上面板，再配置模型

### 设置面板凭据

1. 启动 NeoBot，进入「面板凭据」。等待探测结果，区分面板尚未启动、尚未设置密码和已有密码待登录。
2. 未设置密码时，填写「新面板密码」与「确认密码」；已有密码时填写「面板密码」。提交后看实际登录验证结果。
3. 如果提示版本不支持，先按版本页或上游方式升级；Desktop 代登录需要 NeoBot `1.2.4a1` 起提供的登录接口，旧版本反复输入密码也不能补齐接口。
4. 验证通过后进入「概览」。能读到版本、运行时长和连接状态，才继续模型与运行数据操作。

面板密码保存到本机密钥库。换机器或恢复配置后，可能需要重新填写，见[备份与恢复](/docs/backup/)。

### 配置供应商和模型分配

1. 在「供应商与密钥」的「API 供应商」填写供应商名称、API 地址和自己的 API Key，并按该页按钮保存。
2. 打开「模型」，在「模型库」添加模型条目。字段由当前 NeoBot 面板提供，使用服务商真实模型标识；可用时使用提供商模型拉取或测试入口确认。
3. 在「模型分配」给各用途选择模型，点「保存分配并重载」。模型库存在条目但用途仍为「未分配」，对应任务就没有可用模型。
4. 进入「部署」检查缺项与 OneBot 对接。同机地址和局域网地址要按 NapCat 实际位置选择，Access Token 必须与协议端一致。
5. 回「概览」「系统与运行」确认连接，再在允许的会话测试一条回复。

「本体配置」支持表单与 TOML 原文。重新读取会丢弃当前草稿；恢复默认首先替换草稿，保存后才生效。页面只读时先检查当前面板会话权限。

![NeoBot 模型页：模型库与用途分配分别检查，保存后再测试回复](/docs/screenshots/framework-neobot-light.png)

## 共同的排错顺序

1. **实例没有启动**：看安装任务和实例日志，确认运行时、依赖与端口。
2. **实例已运行，面板读不到**：先查 WebUI / Dashboard 是否就绪，再查凭据和版本。
3. **面板能用，QQ 不回复**：查协议 Bot 在线状态、OneBot 连接、模型分配、名单与触发条件。
4. **只有某个插件或模型失败**：用最小的一条指令或问题复现，查看该次调用日志；先排查它自己的配置和上游服务。
5. **改完没有生效**：看是否还有未保存草稿，是否需要重启，有没有其他窗口覆盖配置。
