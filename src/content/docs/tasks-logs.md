安装失败和 Bot 不回复，需要看的日志不同。先确定问题发生在哪一步，再打开对应入口，会比把所有日志都翻一遍快。

| 发生了什么 | 先看哪里 |
| --- | --- |
| 下载、安装依赖、部署或更新失败 | 侧栏「任务」中的对应任务详情 |
| Bot 启动后退出，或 QQ 登录异常 | 该 Bot 的日志 |
| 应用端启动失败、插件或模型报错 | 应用实例详情「日志」 |
| Desktop 保存、SSH 或界面操作报错 | 「设置 → 日志」 |
| 接口调用失败、收不到事件 | [调试台](/docs/debugging/)的响应、通道和事件 |

## 在任务队列里看完整进度

1. 发起安装或部署后，打开侧栏「任务」。切换页面不会停止后台任务。
2. 用「进行中」筛选找到当前任务，确认标题和目标主机。
3. 选择左侧条目，在右侧看状态、耗时、进度与步骤日志。
4. 下载过程中留意当前源、速度和换源原因；Docker 拉取还会显示镜像层进度。
5. 等待终态。失败时记下具体步骤与第一条错误，不要只截取最后一句「任务失败」。

![任务队列：左侧定位任务，右侧检查进度与步骤日志](/docs/screenshots/tasks-light.png)

排队中的任务尚未开始；进行中的百分比也不一定匀速增长。下载完成后还可能有解压、安装或验证步骤，不能只看文件下载进度判断完成。

## 取消、强制停止和清理

选中任务后，按界面提供的入口取消排队或停止。系统包管理器、Docker 安装等正在修改系统的任务不能安全强停，按钮会说明原因；先等待当前步骤结束。

取消不是完整回滚，也不表示此前下载或安装的内容全部撤销。重试前先检查任务说明和组件检测结果，避免重复启动安装。

「已结束」包含成功、失败和取消的任务。清理已结束条目会移除列表记录，不是在卸载组件。需要保留排错信息时，先复制步骤日志和任务 ID，再清理。自动清理的时间可在「设置 → 监控 → 任务队列」调整。

## 检查 Bot 日志

1. 到「机器人」，找到出问题的 Bot，打开日志入口。
2. 对照你点击启动的时间，从启动阶段开始看：QQ／运行时路径、端口、WebUI、登录状态和 OneBot 连接。
3. 实例启动后立即退出时，保留退出前的错误；只是 QQ 未登录时，回到登录入口处理。
4. 如果你准备重试，先记下原始错误，再只修改一项配置。

![Bot 日志：把错误与启动时间、协议端和账号对应起来](/docs/screenshots/bot-logs-light.png)

常见区别：进程运行不等于 QQ 在线，QQ 在线也不等于应用端已对接。OneBot 报连接拒绝时检查监听进程、地址和端口；鉴权失败则核对两端 token。详细路径见 [连接配置](/docs/connections/)和 [排错](/docs/troubleshooting/)。

## 检查应用端日志

1. 打开「应用端」，进入对应实例的「日志」。
2. 先确认是不是正确实例和主机，再看启动阶段的依赖、配置解析和监听端口。
3. 对「没有回复」，观察发送测试消息的时刻：是否收到事件、匹配规则、调用模型或插件报错。
4. 使用上游 WebUI 时，核对其运行状态与日志，不要在两个入口同时改配置。

日志暂时为空时，确认实例已经启动；「等待新日志」也可能只是当前没有新输出。AI 请求失败要分清模型名、鉴权、额度、服务网络和会话规则，按错误逐项处理。

## 查看 Desktop 自身日志

1. 到「设置 → 日志」。
2. 用级别筛选与关键词搜索缩小范围，例如 SSH、某个组件名或报错中的路径片段。
3. 日志持续滚动时暂停自动滚动，再阅读操作前后的上下文。
4. 点刷新重新读取。需要完整文件时用「打开位置」到日志目录查看。
5. 点复制时会复制当前可见日志。提交前检查当前筛选，别把关键上下文过滤掉。

字号太小时可用工具栏放大。日志页不需要点「保存设置」，搜索与筛选用于当前查看。

## 发 Issue 时给出可复现的信息

推荐按下面的格式整理，方便别人复现：

```text
Desktop 版本：
协议端及版本：NapCat / SnowLuma
运行位置：本机 / 远端 Linux / 远端 Windows
部署方式：原生 / Docker
应用框架及版本（涉及时）：
我做了什么：
1.
2.
预期结果：
实际结果：
错误时间与完整错误：
```

附上相关任务步骤或出错时刻前后的日志，并隐藏 token、密码、API Key、邮箱授权码、SSH 私钥及私人消息。保留错误码、端口关系和经过脱敏的路径，通常比只有一张弹窗截图更有用。
