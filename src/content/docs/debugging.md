Bot 已登录却不回复、聊天收不到消息，先用调试台把问题缩小：是连不上协议端，还是接口报错，或者事件没有送来。调试台会调用真实 Bot；发送消息、撤回、禁言等操作也会真实生效。

## 第一次调用：读取登录信息

1. 启动 Bot 并完成 QQ 登录，打开侧栏「调试台」，或点 Bot 卡片的「调试」。
2. 在顶栏选对目标 Bot，第一次保留「调用」通道为自动。
3. 点「搜索接口」或按 `Ctrl+K`，搜索 `get_login_info`，打开对应接口。
4. 在中栏查看接口「文档」和「参数」。该接口不需要业务参数，JSON 使用 `{}` 即可。
5. 点击发送，或在调试台按 `Ctrl+Enter`。
6. 在响应区核对返回的账号与昵称，检查 `status`、`retcode` 和 `data`。常见成功响应是 `status: "ok"`、`retcode: 0`；最终以当前接口文档和协议端回包为准。

![调试台：左侧选接口，中间看参数与响应，右侧看事件](/docs/screenshots/debug-light.png)

这次只读调用成功，说明当前调用通道可用。它还不能证明事件接收正常，下一节再单独检查。

## 调用通道和事件来源分开选

顶栏有两个通道选项：

- **调用**决定发请求走哪条。自动按内部通道、WS、HTTP 的顺序选择能用的通道。
- **事件**决定右栏从哪里接收。自动按内部通道、WS 的顺序选择，普通 HTTP 调用通道不能替代事件连接。

打开下拉后可以看状态、地址、打码 token 和能力，再点「测试连通」。通道异常时先记录它的错误，返回 [Bot 连接配置](/docs/connections/)核对地址、方向、端口和 token。不需要先把所有通道都打开。

## 看一条真实事件

1. 选好目标 Bot 和「事件」来源，检查右栏接收状态。
2. 用测试好友向 Bot 发一条唯一文字，例如 `事件检查 001`。
3. 在右栏「聊天」视图找这条消息，再切到「列表」核对时间和事件类型。
4. 点事件查看原始 JSON，确认发送者、目标群或私聊、消息内容是否符合预期。

右栏可按消息、通知、请求、调用、元事件筛选，也可搜索文字、名字、QQ 号或接口。找不到消息时先重置筛选，排除把消息类型隐藏了的情况。

「暂停显示」只冻结画面，后台继续接收，恢复后跳到最新。「停止接收」会停止当前接收过程；两者用途不同。清屏只清这里的显示，不会关闭接收。

## 用表单或 JSON 填参数

1. 从接口目录选择需要检查的接口，先读「文档」确认用途、权限和参数类型。
2. 在「参数 → 表单」填写。群号、好友、消息等字段会按接口提供选择器。
3. 切换到「JSON」，核对最终发出的对象；表单和 JSON 使用同一份参数。
4. 确认目标 Bot 后发送，阅读响应和耗时。涉及群管理等操作，先在你有权限的测试群验证。

JSON 语法错误时，表单会锁住并提示出错行。修好 JSON 后恢复；不要通过切换视图绕过错误。自由输入的接口或目录里没有的变体可能只能用 JSON，协议端不支持时也会返回错误。

响应不成功时保留 `retcode` 和错误描述。超时表示没及时收到结果，不能据此认定操作没有执行；涉及发消息等动作时，先核对目标端，再决定是否重试。

## 多标签页、历史与响应对比

每个请求可留在独立标签页，便于对照同一接口的不同参数。切换 Bot 后也要看响应来源：显示的可能是上一次 Bot 的回包，响应区会标明来源。

在左栏「历史」选择记录，可查看当时参数和回包，**打开历史不会自动重新发送**。需要重放时，先核对 Bot、参数和接口副作用，再发送。

排查改配置前后的变化时，使用历史的「对比响应」，选择同一接口的两条记录，查看并排 JSON 差异。清空历史会删掉全部历史及当时响应，即使当前有筛选也一样；收藏不受影响。

## 把常用请求存为收藏

1. 在中栏点「收藏」，或从历史记录收藏一条请求。
2. 起一个能说明用途的名字，例如 `检查当前账号`，确认参数再保存。
3. 在「收藏」中新建文件夹，按日常检查、群管理等用途整理；可拖动排序、移动或重命名。
4. 再次使用时，先打开核对，或使用「在当前 Bot 上发送」。危险接口会要求确认。
5. 需要分享时使用「导出收藏」，另一台 Desktop 可通过「导入收藏」读取。

收藏保留接口和参数，不会因为换了 Bot 自动把业务目标改成另一个账号。导出前检查参数中的私密信息。

## 导出调用代码

在当前请求中打开「导出调用代码」，可生成 curl、JavaScript 或 Python 片段。先选好实际调用通道，确认动作和参数有效，再复制。

代码里的 token 可能是打码值，缺少可导出地址时也会带占位提示。复制后先按对话框说明替换地址与真实 token，随后在自己的环境验证。不要把含真实 token 的代码发到公开 Issue。

## 工作区和独立窗口

顶栏可以将调试台弹出为独立窗口，适合同时查看 Bot 日志。工作区会保存标签草稿、布局及收藏；调用历史不随配置 ZIP 导出，备份范围见 [备份](/docs/backup/)。

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+K` | 搜索接口 |
| `Ctrl+Enter` | 发送当前请求 |
| `Esc` | 取消正在进行的调用（可取消时） |
| `Ctrl+W` | 关闭当前请求标签 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 切换请求标签 |
| `Ctrl+Shift+T` | 重开关闭的标签 |

对话框、终端或编辑器已经处理快捷键时，调试台不会抢走同一按键。

## 根据结果继续排查

| 检查结果 | 下一步 |
| --- | --- |
| `get_login_info` 都失败 | 检查 Bot 进程、登录、调用通道连通性及鉴权 |
| 调用成功，但右栏没有消息 | 检查事件来源、接收状态、筛选和 WS 连接 |
| 调用和事件均成功，应用端不回复 | 去应用端检查适配器、插件／模型、会话规则和日志 |
| 一个接口失败，其他只读接口成功 | 读该接口文档，核对协议端版本、参数和权限 |
