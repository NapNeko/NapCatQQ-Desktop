准备升级或换电脑时，先导出一份配置。如果只是系统盘快满了，使用数据目录迁移；配置 ZIP 和整份数据迁移解决的是不同问题。

| 你现在要做什么 | 使用哪个入口 |
| --- | --- |
| 保存当前设置，或准备在另一台电脑重新搭建 | 「设置 → 数据 → 导出 ZIP」 |
| 从以前的配置包恢复 | 「设置 → 数据 → 打开导入向导」 |
| 把当前电脑的 Desktop 数据搬到另一块盘 | 「设置 → 数据 → 数据根目录 → 迁移」 |
| 释放已下载安装包占用的空间 | 「设置 → 数据 → 下载缓存 → 扫描与清理」 |
| 更新 Desktop 程序 | 「设置 → 关于 → 检查更新」，或安装新版本 MSI |

![数据页提供配置备份、目录迁移与下载缓存清理入口。](/docs/screenshots/settings-data-light.png)

## 导出一份当前配置

1. 先保存你刚修改的 Bot、应用端和设置。导出针对当前已经保存的配置。
2. 打开「设置 → 数据」。
3. 在「配置备份」中点击「导出 ZIP」。
4. 按保存窗口选择一个容易找到的位置，保留原 ZIP。可以给外部保存的副本加上日期，方便分辨。
5. 若同时准备换机，另行备份框架程序、插件、数据库和聊天消息等独立数据，并记录原来的主机与安装路径。

**完成后应看到什么：** 选定位置出现配置 ZIP。先保留它，后面导入失败或恢复条件暂时不满足时仍可以再次使用。

### ZIP 中有哪些内容

| 内容 | 包含的范围 |
| --- | --- |
| Desktop 与 Bot | 外观、功能开关、运行与通知设置、Bot 连接配置 |
| 远端主机 | 服务器档案与连接参数 |
| 应用端实例 | 实例档案、Bot 关联、领养时保存的回滚快照 |
| 框架配置 | Karin、NoneBot2、AstrBot、MaiBot、Koishi、云崽、NeoBot 的核心设置、模型与插件配置；麦麦自定义提示词及版本 |
| 聊天偏好 | 账号用途、后台接收、托盘通知、忽略与隐藏群、界面布局 |
| API 调试台 | 工作区、标签页草稿、布局、收藏与文件夹 |
| SnowLuma | 全局 WebUI 端口与密码覆盖设置 |
| 界面与终端 | 终端设置、常用命令、布局、Bot 手动排序、麦麦聊天昵称 |

**需要另外保存：** 系统密钥库、SSH 私钥、组件与应用程序、插件程序、数据库、缓存、日志、API 调用历史、聊天消息记录。插件配置恢复后，插件程序仍需独立安装。

配置 ZIP 也可能包含敏感信息：框架配置原文中已有的 OneBot token、模型 API Key、通知凭据或密码会随文件保存。因此不要把配置包公开附在 Issue 中。SSH 密码、GitHub Token 等保存在系统密钥库中的凭据不在包内，换机后重新配置。

## 把配置恢复到当前电脑

建议在安装好 Desktop 后、正式启动实例前完成恢复。导入会先检查来源和目标，再列出准备恢复的项目。

1. 打开「设置 → 数据 → 打开导入向导」。
2. 选择配置 ZIP，或把配置文件夹拖入向导。旧版 ZIP 与旧的扁平配置文件夹仍可使用；新的配置包使用 v2 格式。
3. 查看校验结果和恢复项目清单，确认来源确实是你要恢复的那一份。
4. 确认导入。Desktop 会先备份目标现有配置，再写入；来源校验失败不会覆盖配置，写入失败会回滚。
5. 导入完成后重启 Desktop，让启动相关设置生效。
6. 逐项检查 Bot、远端主机、应用实例的路径和连接情况，再启动它们。

来源包中缺少的项目会保留目标当前配置。恢复不会凭空补齐没有导出的程序、插件和数据库。

### 换机后为什么不能直接启动原来的应用

应用实例档案保留原主机与安装路径。新电脑不一定存在同一个目录，也不一定已经安装对应框架。

1. 在目标主机独立准备运行时、框架与插件程序。
2. 核对实例指向的主机和安装路径，确保目录属于对应框架。
3. 停止该实例，再恢复框架配置。
4. 完成后检查模型、插件和 Bot 关联，再启动验证。

框架配置按原文件恢复，会保留原来的注释、格式和自定义字段。如果需要保留数据库或历史记录，请按框架自己的备份方式处理，不能用配置 ZIP 代替。

## 出现「待恢复」时怎么做

### 框架配置待恢复

框架还没安装、实例正在运行或远端暂时无法连接时，Desktop 会把配置保存在数据目录中的待恢复副本里。看到此提示后，不用反复重新导入 ZIP。

1. 完成对应框架的安装。
2. 停止要恢复的应用实例。
3. 如果是远端实例，恢复 SSH 连接；服务器档案的地址、端口或用户名有变化时，去「远端」重新测试连接。
4. 回到「设置 → 数据」，点击「重试恢复框架配置」。
5. 确认恢复完成后再启动实例。

远端恢复会重新核对 SSH 的地址、端口和用户名，避免写入旧主机。有待恢复配置的实例会提示先恢复再启动；待恢复副本也会随下次导出保存。

框架文件或 Desktop 配置写入失败时，已写入的框架文件会一起回滚。如果远端断线导致回滚失败，按界面明确列出的文件检查，不要假设目标目录已经完整恢复。

### 界面偏好待恢复

如果配置文件已导入，但浏览器存储中的界面或终端偏好写入失败，数据页会出现「重试恢复界面偏好」。修复存储问题后点击它即可单独重试，不必为了界面布局再次覆盖整份配置。

## 把数据从系统盘迁到另一块盘

默认数据根为 `%ProgramData%\NapCatQQ Desktop`，实际位置以「设置 → 数据」显示为准。迁移会整树复制配置、密钥、组件等数据；它适合当前电脑换盘，不等同于可在任意电脑直接使用的配置包。

1. 在目标磁盘创建一个空文件夹，例如 `D:\NapCatData`。你选择的文件夹本身就是新的数据根，Desktop 不会再自动追加产品名。
2. 在「数据根目录」旁点击「迁移」。
3. 阅读向导，点击「选择目标文件夹」，选择刚创建的空目录。
4. 核对目标路径、预计复制容量和「将复制的结构」。如有阻止原因，先按提示处理；本机运行中的 Bot 会在迁移前停止。
5. 点击「开始迁移」，等待复制完成。复制中可以使用向导提供的「取消复制」。
6. 复制完成后，在完成页核对「新数据根」「旧数据根」以及可能出现的警告，检查复制结果。
7. 旧副本可以先保留。如果现在就确认要清理，在**这次完成页、重启之前**点击「删除旧目录」并确认；这个完成页不会在重启后保留。
8. 按向导重启 Desktop，新的数据根在重启后使用。再到「设置 → 数据」核对新路径，并检查组件与 Bot。

迁移不需要管理员权限；旧目录只有确认后才删除。目标目录不空或预览有阻止原因时，先重新选择目录，不要手动覆盖旧数据来绕过提示。远端 Windows 的机器代理和用户数据有自己的目标路径，控制端本机的数据根不决定远端路径。

## 清理下载缓存

下载失败后留有旧包，或更新几次后想释放空间，可以用专门的清理入口。

1. 等待正在进行的安装、更新、迁移或其他清理结束。
2. 打开「设置 → 数据 → 下载缓存 → 扫描与清理」。
3. 查看各类别的文件数、估计大小和保留或跳过数量，勾选要清理的类别。
4. 点击「清理所选缓存」。
5. 查看已删除、跳过和失败数量；如有剩余，展开「查看未清理项目的原因」。需要重新核对时点击「重新扫描」。

清理只针对 Desktop 自有的安装包、旧更新包和下载暂存文件，不会清除配置、迁移备份、安装日志、已安装组件、聊天记录、另存的文件或 Windows Installer 系统缓存。

最近 24 小时的更新包会保留；历史系统临时下载只清理满 7 天且所属进程已经退出的文件。安装失败后保留的包一旦清掉，下次重试就需要重新下载。

占用中、权限不足、只读或路径为链接的文件会保留，并显示原因；其他符合条件的文件仍会继续处理。清理不会提权、修改权限或移除只读属性，显示的容量是文件大小估计。

## 更新 Desktop

1. 先按上文导出配置。
2. 打开「设置 → 关于」，点击「检查更新」，按界面提示下载并安装；也可以从 [最新发布页](https://github.com/NapNeko/NapCatQQ-Desktop/releases/latest) 下载新版 Desktop MSI，直接覆盖安装。
3. 更新后查看版本、Bot 与应用实例，再按原流程启动。
4. 如果使用远端 ncd-watch，另到组件页检查它的版本。升级 Desktop 不会自动替换远端 ncd-watch 二进制。

带 `watch-v` 的发布属于远端值守组件，Desktop 安装包使用 Desktop 的版本。更新包下载失败时，接着检查 [网络代理与下载线路](/docs/network/)；值守维护见 [ncd-watch](/docs/watch/)。
