# MCP 安全复核（2026-10-23）

本记录对应 MCP 扩展功能的第二轮源码复核。面向代码审阅者；用户接入与权限说明见[主仓接入指南](../user/mcp.md)，完整工具参考和安全说明另见 `web` 分支的 `mcp`、`mcp-tools`、`mcp-security` 文档页。

## 范围与信任边界

复核覆盖 `ncd-mcp` 的 HTTP 入口、JSON-RPC、权限与生命周期、OneBot 调用参数和输出，以及它实际经过的 DebugManager、只读检查入口、系统凭据存储、Tauri 设置应用和复制令牌流程。检查依据包括 [MCP 2025-11-25 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)与[安全最佳实践](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)。

- 无令牌的网页、重绑定域名和本地连接不应取得工具访问权。
- 有令牌的客户端受 Desktop 当前权限约束；工具输入、消息、日志与上游目录均不构成授权。
- Desktop 主窗口及其原生 IPC 属于可信配置边界。它不是独立于客户端的人工审批系统。
- 操作系统账户已被控制、恶意替换 Bot 后端实现、模型服务如何处理已返回数据，不属于本轮代码能隔离的范围。

## 发现与修复

| 问题 | 可达路径与影响 | 修复 |
| --- | --- | --- |
| 动作与参数黑名单存在遗漏 | 写模式客户端可通过 `request_decrypt_key` / `get_clientkey` 及 `db_path`、`files`、`images` 等字段触及密钥或文件能力 | 改用本地固定审核动作表与逐动作参数白名单；未知动作不开放。消息段限制为明确支持的类型 |
| 旧请求可跨越撤权继续执行 | RPC 仅在 dispatch 前检查代际，异步等待后的执行未绑定原权限代际；关闭服务与放宽离线配置混在一次应用中存在顺序窗口 | 权限状态与挑战统一同步，入场请求绑定可撤销代际，运行实例取消同时终止旧请求；订阅登记使用原入场代际。关闭时先撤销旧实例，再更新离线权限 |
| 未认证连接没有独立限额 | HTTP 工具并发限额在请求头解析后才生效，慢连接可占用独立连接任务；停止监听器也不等于停止已接受的 socket | 增加连接限额、连接寿命和实例取消边界，保留请求体和工具执行的独立期限 |
| 令牌存储降级削弱保护 | 原通用 SecretStore 在系统凭据服务出错时写入本地加密文件，其密钥位于同目录；降级写后重新读取旧系统凭据也可能让轮换结果失真 | MCP 单独注入 `SystemSecretStore` 并使用新键 `mcp:bearer_token:v2`，不复用旧凭据；系统凭据不可用就返回错误，不降级、不把失败当作轮换成功。升级后重新复制连接配置 |
| 设置失败可跳过已保存的撤权 | 设置已写盘后，自启动或聊天热应用报错会提前返回，MCP 仍保留旧监听器、宽松权限或 API 调试开关 | 持久化成功后优先应用 MCP 和 API 调试安全设置，再执行其他可能失败的热应用 |
| 标记只读的查询会触发文件修复 | 工作区、收藏和历史查询使用通用惰性加载，冷启动时会清理临时文件、隔离损坏文件或重写历史 | MCP 使用独立只读加载，不接管 GUI 缓存；损坏文件报错，原文件保留，缺文件返回默认空状态 |
| 历史记录预算只覆盖回包 | `params`、错误等非回包字段未计入总量，详情补读还会重新经过无界行读取 | MCP 冷扫描和详情补读限制单行与总扫描量，并对保留的完整记录计费；超限明确报错，不改原文件，GUI 原路径不变 |
| 敏感输出匹配不完整 | 非标准密钥名、带空格或截断的凭据文本可能逃过原规则 | 扩充敏感字段与文本回归；保持结构化字段过滤、深度/节点/字节上限，不把模式脱敏描述为完整 DLP |

| 检查 | 结果 |
| --- | --- |

| `cargo test -p ncd-config --lib system_secret_store:: -- --test-threads=2` | 2 项通过 |
| `cargo test -p ncd-runtime --lib onebot_debug:: -- --test-threads=2` | 165 项通过 |
| `cargo check -p ncd-tauri --all-targets` | 通过 |

| 改动范围内 Rust 格式与 diff 空白检查 | 通过 |

Rust 命令仅在本次进程中清空 `RUSTC_WRAPPER`，不改变用户的持久编译配置。上述 237 项测试包括临时文件、Mock 和本机 HTTP/socket 检查，不代表真实 Bot 验收。

仍需按以下边界使用：

- 所有持有同一 Bearer Token 的客户端共享权限，没有每客户端、每 Bot 的独立授权范围。即使只读，也可能取得聊天记录、QQ 号和服务器地址。
- 确认挑战只保证调用参数绑定、有效期和一次使用。客户端能自行取得挑战并携带确认令牌再次调用，因此挑战不等于用户批准；需要独立人工审批的部署应保持只读。
- 撤权或超时会中断尚未继续执行的旧请求，但无法撤回已发给上游的消息，也无法回滚已提交的本地 I/O。收到中断或超时后应先核查结果，不能直接重试写操作。
- 日志、事件与动作返回值属于不可信内容。结构化投影和脱敏不保证识别任意自然语言、编码或自定义格式中的秘密，也不能消除提示注入。
- 只读 OneBot 调用仍会连接已配置的 Bot、产生运行时连接状态与调用历史；纯检查工具及工作区/历史读取的无修复保证不应扩大为“整个进程绝不写盘”。
- SnowLuma 的本机日志来源可能是共享 daemon，不能承诺按账号完全隔离。
- 本轮不发送真实 QQ 消息、不修改真实群状态；没有以真实 Bot 验收替代模拟、临时文件和本机 HTTP 回归。
