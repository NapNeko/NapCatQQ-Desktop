# 远端 SnowLuma 启动缓存生命周期

范围：Linux SSH 原生 SnowLuma 的初始化、共享 daemon、身份探测和隧道；不包括 Docker 与远端 Windows 启动。

| 状态 | 创建与复用 | 失效与释放 |
| --- | --- | --- |
| 按主机初始化锁 | 同一 server 的首次布局探测共用一个锁和取消令牌，不同 server 独立 | 注册表仅保留 Weak；最后一个初始化任务/等待者结束或取消后锁释放，下次访问清除失效键。断线/退出移除槽并取消；布局探测完成后提交前核对槽身份，旧初始化不能在清理后重新写回 daemon 注册表 |
| daemon/backend 注册表 | 按 server 保存生命周期所有者，backend 持有存活 poller | 保持实例身份，避免临时 Drop 把运行中 Bot 误报掉线；它们的存在不代表连接或启动成功，连接相关缓存单独失效 |
| 连接代 CancellationToken | 每个 daemon 一代；start、reconcile、启栈、VNC 操作归属取得令牌时的连接代 | router 在同一个连接代门锁内核对 ServerManager 当前 Host 身份并替换，迟到的旧 Host 不能覆盖已发布的新 Host。换 Host、detach 先撤销旧代，取消正在等待的旧任务，再清本地状态；后台启动或恢复不能在断线清理后重新安装旧 poller |
| node 身份 | 完整初始化成功后保存 PID/starttime 和配置、凭据文件元数据；首次允许 PID 文件或 /proc 发现导入/systemd node，后续仅探已验证 PID。记录默认 secret 的缺失状态，并包含实际采用的外来 secret 路径 | PID/启动时间、配置/凭据变化、缺失默认文件重新出现、探测失败、完整初始化失败、最后租约释放、换 Host、detach 都失效；失败没有负缓存，后续请求可重试 |
| reconcile 成功态 | 接管现有 QQ 后保存身份，仅用于同代后续 reconcile | 不能替代完整启动预检；首次普通启动仍完整校验一次，成功后才允许普通启动复用 |
| Bot 租约 | 启动先占位，backend 完成注入后确认；reconcile 已观察到存活 QQ，可直接确认 | 启动失败只归还自身租约；断线/换 Host 回收未完成占位，暂时保留已确认账号；reconcile 确认 QQ 已不存在后 detach_status_poller 同时归还租约。实际启动与探测/清理共用已有 per-Bot reconcile 门锁，旧探测不能释放同 Bot 新启动的租约；等门锁时仍可取消。探测失败/离线不能当成已退出 |
| daemon 本地端点与远端端口 | 成功建立隧道后保存，身份和注册表均有效才复用 | 最后本地租约释放先清本地缓存与隧道；远端仍有 QQ 或状态未知时只保留远端进程，不保留本地成功缓存 |
| SSH 隧道注册表 | 每 server 一个槽位，槽内串行创建双隧道，其他 server 不等待这台机的 SSH | 引用归零、drop_server、shutdown_all 或创建失败移除槽；远端 open 完成后核对槽身份，已移除槽的迟到结果丢弃，不能覆盖重连后的新槽 |
| metrics_node_env | 当前共享 node 下次启动应使用的配置；其他账号通过注册表热更新 | 这是待应用配置，不是“服务已就绪”的证据；不因账号增加重启共享 node |

没有新增 TTL。缓存依据进程、文件、连接代和租约的真实生命周期，而不是经过若干秒后猜测是否有效。

锁顺序：全局主机/隧道表仅用于取出或替换 Arc，不跨 SSH I/O；远端操作只持本主机锁。连接代锁覆盖当前 Host 身份校验、撤销与切换，撤销会先让占用启栈锁的旧远端操作退出。同 Host 的 router 查询只做本地身份核对，不等待正在启栈的长锁。Bot 启动与 reconcile 只互斥同一 Bot，其他账号保持并发。

回归覆盖：批量复用、配置/进程身份变化、隧道移除、连接替换与迟到旧 Host 拒绝回填、撤销在途身份探测、最后租约与外部 QQ、同 Bot 启动/清理互斥与等待取消、失败后重试、慢主机与其他主机隔离、drop/shutdown 后迟到隧道拒绝回填、初始化锁回收。真实 /proc 脚本测试只在 Linux 运行，包含无 PID 文件和已验证 PID 直探；Mock 测试不能代替真实远端耗时与多账号登录验收。
