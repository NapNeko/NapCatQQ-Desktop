# 测试取舍与夹具边界

测试用于发现会影响用户的回归。新增用例前先说明：什么输入或事件触发问题、用户会看到什么错误、现有哪一层尚未保护它。文件数量、分支数量和覆盖率不直接决定是否加测试。

## 在拥有行为的层测试

| 行为 | 主要保护位置 | 上层保留什么 |
| :--- | :--- | :--- |
| 配置兼容、迁移、原子写入与失败回滚 | Rust 配置模块及真实临时目录集成测试 | 保存失败、草稿保留、错误展示 |
| 协议解析、鉴权、参数安全、流式收发 | backend / onebot / runtime，必要时用回环 HTTP / WS 服务 | 参数组装、错误与成功状态衔接 |
| 并发取消、连接代次、迟到结果、资源释放 | 拥有状态的 manager / store / hook | 一个有代表性的用户操作流程 |
| TS 派生规则、排序、去重、归一化 | 所属 domain 模块 | UI 不重复排列全部输入组合 |
| 键盘、焦点、对话框、用户操作 | 组件行为测试 | 通过可访问角色、可见结果和回调断言 |
| 浏览器预览假数据 | 少量预览冒烟测试 | 能打开、能交互、订阅能释放；不作为真实后端验收 |

上下层同名测试不一定重复。例如 Rust 保证不接受旧连接调用，前端保证旧响应不覆盖新页面，两者的故障边界不同。优先保留迁移、凭据隔离、数据丢失、并发恢复和真实缺陷的回归用例。

## 删除与合并

- 可以删除：只检查夹具能读取自己、只断言 mock 返回预先写好的数量/昵称/延迟、把静态映射表再抄一遍、用运行时断言重复 TypeScript 已穷尽的联合类型。
- 可以合并：同一个行为的重复布置与相同断言。确有不同等价类时用小型参数表；不要为了减少用例数字把无关场景塞进一个大测试。
- 保留：外部协议字段与兼容样本、缺省和显式值的语义差别、危险操作提示、布局算法、可读性/二维码对比度等有明确失败后果的约束。
- 文案、主题分组、图标和动画曲线的日常调整不应要求同步改一份金样。参数中的账号、端口、错误原因是否正确显示仍是可测试行为。
- 删除已有生产行为回归时，在改动说明中指出保留覆盖的位置；不能把“目前都绿”当作删除依据。

## 夹具只承担必要布置

- 单个测试文件需要的数据就近声明，只突出该场景变化的字段。简单的值对象允许少量重复，不为消除几行重复建立全局工厂。
- 只有多个调用方确实共享相同语义，才放进共享 test-support；不预建未来可能需要的 setter、错误类型、快照和失败注入接口。
- `BotConfigBuilder` 只保留已有调用方需要的身份和运行场景设置。特殊字段在用例内修改构造后的强类型配置。
- `TempWorkspace` 使用 `tempfile` 管理目录生命周期，只补嵌套写入与相对路径约束。不要再维护自己的目录命名、重试和清理框架。
- `MockSecretStore` 直接实现 `SecretStore`。失败注入按实际场景添加；当前只需要模拟一次写入不可用，验证迁移失败后旧凭据仍在。
- 共享 DOM setup 只提供环境缺失的浏览器 API。业务 service、Tauri 调用和失败结果由用例显式设置，不全局伪造成功。
- 前端模块 mock 使用 `vi.hoisted` 声明实际依赖的方法，直接交给 `vi.mock`。不为初始化顺序再维护 Proxy 转发器；查询缓存、虚拟列表尺寸和异步结果仍由各场景控制。
- 文件测试显式传入临时目录，备份和清理也必须留在这个目录内。系统目录在生产入口解析，不让单测操作真实桌面或用户配置。
- JSON 等外置样本只用于需要固定字节、上游协议结构或旧格式的测试。小对象直接写在用例里；无使用者的样本随辅助代码一起删除。

## 验证方式

实现完成后统一验证。前端改动使用 `pnpm run typecheck` 与 `pnpm run test:related <源文件>`；测试基础设施调整运行完整 `pnpm run test:unit`，需要同时核查覆盖率时以 `pnpm run test:coverage` 代替，避免重复执行整套。覆盖率用于发现未覆盖风险，不通过添加静态断言或降低阈值满足数字。

Rust 使用 `cargo test -p <crate> <过滤词>`。共享夹具接口调整还要编译全部调用方的测试目标（`cargo check --workspace --all-targets`），并执行受影响集成测试。IPC 类型变化才额外导出绑定。

本地最多 2 个 Vitest worker、2 个 Cargo 编译任务和 2 个 Rust 测试线程，重型检查顺序执行。需要真实 QQ、SSH、容器或桌面会话的 ignored 冒烟单独执行；离线测试通过不代表这些集成已验收。测试入口与 CI 见 [贡献指南](../../CONTRIBUTING.md#检查与构建)。
