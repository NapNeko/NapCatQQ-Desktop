# 内存边界与资源生命周期修复

2026-10-07。基于三份内存调查报告及 `43fef0ec` 的生产代码修复，分支 `codex/memory-bounds-fix`。

## 已实现的边界

| 对象 | 保留策略 |
| --- | --- |
| 原生字体 | 注册所有者同时持有 factory 与 loader；字体集合、format、最后一个 layout 释放后注销，初始化失败也清理 |
| 每 Bot 事件 ring | 5000 条、16 MiB JSON payload、单条 1 MiB；缓存与实时队列共享不可变事件 |
| 待推事件 | 2 MiB 达限即推送；订阅补发每批最多 500 条或 2 MiB |
| 每账号消息工作集 | 50 条逻辑页；阅读锚点附近页与最新页；最多 1000 条、估算 8 MiB |
| 每账号档案保留 | 独立保留最多 5000 条、估算 16 MiB；与工作集共享消息，沿用原档案格式 |
| 转发缓存 | 全局 64 条、估算 8 MiB、5 分钟 TTL；按账号与通道隔离 |
| 媒体请求 | 图片解析 4 并发、最多 256 等待；转发读取 4 并发、最多 64 等待 |

事件超出单条缓存预算时，已订阅消费者仍收到完整正文；补拉中的同一 seq 是明确的 Dropped 标记，标记之后淘汰不重复计算正文丢失。预算约束的是驻留缓存，不是网络读入或序列化峰值。

前端批量摄入后统一去重、排序和裁剪。历史游标跟随保留页，中间缺口可按消息 ID 重取；回最新恢复近期页并刷新。工作集回收不再把已有档案一起覆盖。发送结果、撤回、失败恢复与交接位置沿用既有流程。

转发卡片只留三行摘要，弹窗关闭清除完整路径；路径超预算后旧层按需重读。长转发列表采用已有虚拟器。debug 的媒体服务捕获账号与通道快照，旧排队请求不会改向新通道。

WebView 报表的 hidden/dormant 仍表达目标状态，新增 appliedHidden/appliedDormant 与 lastError 表达执行反馈。Windows 可见性经 controller 设置并读回，Low 在 COM 返回成功后确认；失败最多安排两次重试。窗口代次与状态代次共同拦截迟到结果，超时请求在 UI 执行前拒绝。成功设置 Low 不等于内存回收已经完成。

## 验证范围

全部实现完成后统一验收：

- `cargo check --workspace --all-targets` 通过。
- 前端覆盖 34 个相关测试文件、303 个用例。首轮三个旧 fixture 未建立活动会话；修正 fixture 后对对应两份文件补验 40/40 通过，保留原历史去重和搜索分页断言。
- `cargo test -p ncd-onebot --lib ring::tests`：14/14 通过。
- `cargo test -p ncd-runtime --lib onebot_debug::receiver::tests`：11/11 通过。
- `pnpm.cmd run build` 的 TypeScript 检查与生产构建通过；本轮前端文件的 Prettier 检查与工作区 Rust 格式检查通过。
- `cargo test -p ncd-tauri --lib webview_scheduler`：17/17 通过，其中包括 4 个 ts-rs 导出测试。
- 字体排版独立存活、最后一个 layout 释放后配对注销的原生测试：1/1 通过。

预算字节是 JSON payload 或对象内容估算，不是 RSS/私有提交硬上限。正在发送的消息临时保留以等待 requestId 回包；原有档案上限之外的单条消息不能承诺跨关闭恢复。上游传输队列仍沿用原条数上限。

本轮保留 Low/Normal 策略。Suspend、GPU 参数、缩略图来源和本地媒体二进制通道需独立测量与协议条件；尚未进行完整 release 的真实账号图多群聊对照，不能将调查中的隔离实验收益作为本轮产品实测。
