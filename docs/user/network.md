# 网络代理与下载线路

打开「设置 → 网络」，修改后点击「保存设置」。新请求立即使用新配置，已经开始的下载继续使用原来的代理和线路。

## 网络代理

| 模式 | 行为 |
| --- | --- |
| 系统代理 | 读取代理环境变量和 Windows 固定代理设置；不执行 PAC 自动代理脚本 |
| 不使用代理 | Desktop 的外网 HTTP 请求直接连接，忽略系统代理 |
| 手动代理 | 使用填写的 HTTP、HTTPS、SOCKS5 或 SOCKS5H 代理 |

例如 `http://127.0.0.1:7890` 或 `socks5h://127.0.0.1:1080`。SOCKS5H 由代理解析目标域名，SOCKS5 在本机解析。需要认证时使用独立的用户名与密码输入框，地址中不要包含账号密码。

排除地址支持逗号分隔的主机名、域名、IP 和网段，例如 `localhost,192.168.0.0/16`。本机回环地址始终绕过代理。密码保存在系统密钥库或本机加密存储，不写入普通设置文件，也不随配置 ZIP 导出；换机后需重新填写。

代理作用于 Desktop 统一网络层发起的外网请求，包括组件包、Desktop 更新包、版本 API 和通过该网络层加载的资源。本机 Bot/WebUI、SSH、远端服务器的 curl/wget、包管理器、Docker 拉取，以及框架自己发起的请求使用各自的网络配置。

## 下载线路

GitHub 公共下载和 Node.js 下载分别选择线路：

- **自动择优**：比较候选源的实际下载速度，下载低速或失败时尝试其他候选。手动代理模式下，自动线路使用原站，通过配置的代理访问。
- **原站**：只请求官方原地址，仍遵循上面的代理模式。
- **固定镜像**：选择内置镜像或填写自定义地址，只使用所选线路；失败后不会自动切换到其他站点。

GitHub 自定义镜像使用「镜像前缀 + 完整原 URL」形式。例如 `https://mirror.example` 对应 `https://mirror.example/https://github.com/owner/repo/...`。Node.js 自定义镜像填写 dist 根目录，例如 `https://registry.npmmirror.com/-/binary/node`，版本路径会追加在后面。

镜像改写仅用于已知的公共 GitHub 与 Node.js 下载地址。带账号密码、查询参数或签名的链接，以及其他下载站点不转发到镜像，但仍遵循代理配置。

## Python 包源

「Python 框架安装 → Python 包源」用于 NeoBot、AstrBot、NoneBot2 等框架通过默认索引安装依赖的任务，可选择跟随 uv 配置、PyPI 原站、清华镜像或自定义 HTTPS Simple API 地址。默认跟随 uv，不覆盖主机已有的环境变量和 uv 配置；地址不能包含账号密码、查询参数或片段。

保存后新提交的安装任务使用新包源，已提交的任务继续使用原选择。该设置控制默认 Python 包索引，不改写上游锁文件或显式声明的包源；MaiBot 等使用上游锁文件的项目继续遵循锁定的来源，也不影响 Python 解释器下载。远端 uv 由服务器自己联网，Desktop 的代理和「测试连接」结果不能证明远端能访问所选包源。

## 测试与排错

「测试连接」使用当前草稿，不需要先保存，也不会更改正在使用的设置。它会检查 GitHub API 和当前下载候选地址，显示 HTTP 结果与响应耗时。响应耗时不是下载速度；自动下载仍会执行吞吐量测速。浏览器开发预览无法执行真实网络测试。

代理认证失败时检查用户名、密码和代理软件的认证设置；连接失败时检查代理是否正在运行及端口是否一致。固定镜像不可用时，可以手动更换镜像或改回自动择优。

GitHub API 的「中转优先 / 直连 GitHub」和 PAT 也在网络页配置。它控制版本元数据的来源，和安装包下载线路分别设置。PAT 只发送给 GitHub API，不发送给下载镜像或 API 中转。
