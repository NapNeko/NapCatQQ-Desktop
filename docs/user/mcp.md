# 使用 MCP 接入 NCD

NCD 提供本机 HTTP MCP 服务，让支持远程 HTTP MCP 的客户端查询运行状态、检查问题和调用已审核的 OneBot 动作。服务默认关闭；开启后默认只读。

## 接入

1. 在 NCD 的「设置 → 运行 → MCP」开启服务并保存设置。端口留为 `0` 时会自动分配并保存，后续启动继续使用这个端口。
2. 等状态显示正在监听，再点「复制连接配置」。配置包含访问令牌，请只粘贴到可信客户端的 MCP 配置中。
3. 客户端选择 HTTP MCP（也称 Streamable HTTP），使用复制配置中的 URL 和 `Authorization` 请求头。不要选 stdio 或旧式 HTTP+SSE。
4. 连接后先调用 `server_status` 和 `get_security_policy`，确认服务状态和当前权限。

复制的配置结构如下；示例中的端口与令牌需要替换为应用实际返回的值：

```json
{
    "mcpServers": {
        "ncd": {
            "url": "http://127.0.0.1:实际端口/mcp",
            "headers": {
                "Authorization": "Bearer 实际令牌"
            }
        }
    }
}
```

客户端的配置入口可能不同。例如需要显式传输类型的客户端，应按它的文档补充 HTTP 类型；不要把这份配置当作通用的 stdio 启动命令。服务使用 JSON 响应，不提供 SSE 事件推送。

服务只监听 `127.0.0.1`。客户端需要运行在与 NCD 相同的系统网络环境中；另一台电脑或隔离容器中的 `127.0.0.1` 无法直接访问。NCD 退出后服务随之停止。

## 可以做什么

当前提供 30 个工具，分成以下几类：

| 需求                           | 工具                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------- |
| 查看服务和权限                 | `server_status`、`get_security_policy`                                          |
| 检查 Bot                       | `list_targets`、`get_bot_runtime`、`diagnose_bot`、`tail_bot_logs`              |
| 检查应用端、服务器和部署任务   | `list_app_instances`、`get_app_runtime`、`list_servers`、`list_component_tasks` |
| 查询 OneBot 动作及通道         | `list_channels`、`list_actions`、`search_actions`、`describe_action`            |
| 调用、事件、调试台工作区与历史 | `call_action`、`test_channel`、事件订阅读取、工作区/收藏/历史工具               |

客户端可通过 `tools/list` 获取完整工具及参数。先用 `list_targets` 获得 `bot_id`；列表类工具按 `limit`、`offset` 分页，运维列表单页最多 200 项。`tail_bot_logs` 只读现有的本机运行时缓存，不会为查询连接服务器或启动 Bot；没有缓存时会明确返回不可用。SnowLuma 日志可能来自共享 daemon。

OneBot 动作目录用于查文档，上游目录包含的动作不一定允许经 MCP 执行。实际允许的动作与分级以 `get_security_policy` 返回值为准：未审核动作、凭据和文件能力始终禁止。消息仅支持普通文本以及 `text`、`at`、`face`、`reply` 消息段；`/help` 等命令文本可以直接发送，文件协议和 CQ 码不开放。

OneBot 调用还需在 NCD 开启「API 调试」，并有可用的 Bot 通道。运维检查和安全策略查询不依赖这个开关。事件采用 `subscribe_events` 后通过 `read_events` 游标轮询；订阅属于写操作，只读模式下不能创建新的订阅。

## 写操作与令牌

只读模式拒绝消息发送、状态修改、订阅创建、工作区保存等有副作用的操作。需要这些能力时，在桌面设置中关闭只读；危险操作还需要单独开启对应权限。MCP 客户端不能自行改变这两个权限开关。

写调用首次返回一次性挑战，客户端需带 `confirm_token` 重放同一工具和同一参数。令牌有效期为 120 秒，使用一次即失效。这个步骤绑定调用参数，**不代表用户已经批准**；客户端仍需取得用户对目标和操作的授权。需要独立人工审批的场景应保持只读。

所有持有同一 Bearer 令牌的客户端共享权限。即使只读，也可能读到聊天内容、QQ 号和服务器地址。工具输出会做有界裁剪与脱敏，但日志、消息和上游文档仍是外部数据，不能作为新的操作指令。

在设置中重置令牌后，旧配置立即失效，需要重新复制并更新客户端。关闭服务、修改权限或重置令牌也会中断旧请求并清理 MCP 订阅。已发送给 Bot 的操作可能已经执行，收到中断或超时后应先核实结果，再决定是否重试。

## 排查连接问题

| 现象                            | 检查                                                                                               |
| ------------------------------- | -------------------------------------------------------------------------------------------------- |
| 无法连接                        | 确认 NCD 正在运行、服务显示正在监听、端口与复制配置一致；确认客户端与 NCD 共用本机网络环境         |
| 服务开启但未监听                | 查看设置页错误。端口可能已被占用，或系统凭据存储不可用；服务不会把令牌降级存到普通文件             |
| `401`                           | 请求头缺少令牌、令牌错误或已经重置；重新复制配置                                                   |
| `403`                           | 使用复制配置中的回环地址和端口，检查客户端是否改写了 Host 或发送其他站点的 Origin                  |
| `409` 或工具提示权限/凭据已改变 | 重新连接并查询状态；对于写操作，先核实是否已经执行                                                 |
| `429`                           | 当前请求过多，稍后重试读取；不要自动重试执行结果不明的写操作                                       |
| 动作被拒绝                      | 检查当前只读/危险权限及 `get_security_policy` 允许列表；文件、凭据和未审核动作无法通过放宽权限开放 |
| Bot 查询或调用失败              | 确认 `bot_id` 来自 `list_targets`，再检查 Bot 运行、登录、API 调试和通道状态                       |

实现和安全边界详见[安全复核记录](../context/mcp-security-review.md)。
