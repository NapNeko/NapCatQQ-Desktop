# 远端 Linux 管理

[返回用户指南](README.md) · [应用端实例](app-instances.md) · [ncd-watch 值守](ncd-watch.md)

Desktop 运行在 Windows，通过 SSH 管理 Linux 主机。协议 Bot 支持远端原生运行和 Docker 部署；应用端的安装、配置和日志也按实例所属主机管理。

## 添加主机

1. 打开「远端」页，添加 SSH 地址、端口、用户名和认证方式。
2. 测试连接，核对首次连接时的主机指纹。
3. 在「组件」页切换到这台主机，检查运行环境并安装所需组件。
4. 创建 Bot 时选择该主机，以及原生或 Docker 运行方式。

SSH 用户需要对安装目录有读写权限；安装系统依赖需要相应的提权权限。Docker 部署需要这个用户能够访问 Docker。私钥和密码不写入项目仓库。

## 选择运行方式

| 方式        | 适用场景                        | 准备事项                                       |
| :---------- | :------------------------------ | :--------------------------------------------- |
| 原生运行    | 直接管理 QQ、协议端与应用端进程 | 在组件页安装运行时、QQ 和框架，检查系统依赖    |
| Docker 部署 | 希望协议 Bot 使用容器运行       | 准备 Docker 环境，在部署流程中选择镜像源与配置 |

常见 Linux 环境可从 Ubuntu / Debian 开始；QQ 所需动态库、Node / Python 版本及架构按具体框架和组件检测结果处理。容器内依赖由镜像提供，不要把宿主机原生依赖清单当成所有部署方式的必装项。

NapCat 使用 WebUI 完成配置和登录相关操作；SnowLuma 通常通过 QQ 图形界面 / VNC 登录。

## 启动失败怎么查

1. **看失败阶段**：分清安装任务失败、进程退出、QQ 未登录、WebUI 不可用或鉴权失败。Bot 卡片、任务队列和日志会给出各自的状态。
2. **原生部署查依赖**：先在组件页检查 QQ 与运行时，补齐提示缺失的系统库。使用终端时，按实际安装路径检查程序，不沿用其他主机的固定目录。
3. **Docker 查容器**：在这台主机的终端执行以下只读检查，确认 Docker 可用、容器是否退出、端口如何映射。

    ```bash
    docker info
    docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
    ```

4. **查登录与连接**：进程或容器运行不代表 QQ 已登录。检查 WebUI / QQ 登录入口，以及 OneBot 配置、端口和 token。
5. **查远端访问**：重新测试 SSH 连接，确认安装目录、权限和隧道。遇到下载失败时可检查网络或更换界面提供的镜像源。

## WebUI 提示 token 错误

NapCat Docker 的有效 token 以容器当前使用的 `webui.json` 为准；启动参数里的初始 token 不一定与已有配置一致。Desktop 会读取实际配置，鉴权失败后重新核对。更新后重新连接 Bot；如果仍失败，检查 SSH 用户能否执行 Docker 命令、容器配置是否可读，以及 WebUI 是否提示限流或两步验证。

不要连续手动尝试大量登录。提交日志时隐藏 token、密码和通知密钥。

## 在 WebUI 修改的连接被还原

Desktop 启动远端 Bot 时会按已保存配置写入 OneBot 连接。在 WebUI 修改后，打开这个 Bot 的「配置 → 连接」，点击「从远端读取」，核对差异并保存到 Desktop。

## Desktop 退出后继续运行和通知

远端任务由远端主机运行，SSH 断开后应分别核对远端进程状态和通知状态。需要 Desktop 退出后继续值守时，在「组件」页选择远端主机并安装 [ncd-watch](ncd-watch.md)。它是独立发布的组件，升级 Desktop 不会自动升级远端二进制。
