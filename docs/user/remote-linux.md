# 远端 Linux 管理

[返回用户指南](README.md) · [应用端实例](app-instances.md) · [ncd-watch 值守](ncd-watch.md)

Desktop 运行在 Windows 或 Linux，通过 SSH 管理远端 Linux 主机。协议 Bot 支持远端原生运行和 Docker 部署；应用端的安装、配置和日志也按实例所属主机管理。

## 添加主机

1. 打开「远端」页，添加 SSH 地址、端口、用户名和认证方式。
2. 测试连接，核对首次连接时的主机指纹。
3. 在「组件」页切换到这台主机，检查运行环境并安装所需组件。
4. 创建 Bot 时选择该主机，以及原生或 Docker 运行方式。

SSH 用户需要对安装目录有读写权限；安装系统依赖需要相应的提权权限。Docker 部署需要这个用户能够访问 Docker。私钥和密码不写入项目仓库。

## 选择运行方式

| 方式        | 适用场景                        | 准备事项                                       |
| :---------- | :------------------------------ | :--------------------------------------------- |
| 原生运行    | 直接管理 QQ、协议端与应用端进程 | 在组件页安装运行时、QQ 和框架，检查系统依赖    |
| Docker 部署 | 希望协议 Bot 使用容器运行       | 准备 Docker 环境，在部署流程中选择镜像源与配置 |

常见 Linux 环境可从 Ubuntu / Debian 开始；QQ 所需动态库、Node / Python 版本及架构按具体框架和组件检测结果处理。容器内依赖由镜像提供，不要把宿主机原生依赖清单当成所有部署方式的必装项。

NapCat 使用 WebUI 完成配置和登录相关操作；SnowLuma 可使用默认开启的 [简化扫码登录](snowluma-remote-qr-login.md)，环境不支持时仍可通过 QQ 图形界面 / VNC 登录。

## 调整 Docker Bot 容器

打开这个 Bot 的「配置 → 容器」，可调整端口映射、追加环境变量、Docker 重启策略和内存上限。内存上限留空表示不限制；环境变量随 Bot 配置保存，WebUI 凭据、QQ 账号、登录和指标所需变量由 Desktop 管理。

在「连接」中新增或启用 HTTP、SSE、WebSocket 服务后，Desktop 会自动补齐 Docker 的 TCP 端口发布。「容器」页列出容器端口、用途和宿主机端口；宿主机端口默认按 QQ 账号加偏移，冲突时直接改这一列。例如 QQ 号为 `10001` 时，容器端口 `3010` 默认发布到宿主机 `3011`。外部程序应连接宿主机端口，Bot 的连接配置仍填写容器端口。

可恢复某一端口的自动映射，也可追加其他 TCP 映射；额外映射仍需要容器内有服务实际监听。反向 WebSocket、Webhook 等主动连接不会增加发布端口。Docker 派生配置会把回环监听转换为容器内 `0.0.0.0`，宿主机发布范围单独控制。

宿主机默认只发布到 `127.0.0.1`，Desktop 和 SSH 隧道仍可访问。需要其它设备直连时，在「容器 → 访问范围」开启外部访问并确认风险，端口才发布到 `0.0.0.0`；这包括 OneBot、WebUI 和 VNC 等管理入口。主机有公网地址时，服务可能对公网可达，请先设置可靠的 token / 密码，并通过防火墙或安全组限制来源。Desktop 不自动开放防火墙。

保存时会自动更新容器配置。运行中的 Bot 在映射或容器设置变化时重建容器，连接会短暂中断，数据卷保留；停止的 Bot 下次启动时应用。如果应用失败，界面会给出原因，已保存的设置仍保留，修正冲突或主机问题后重试启动即可。

Desktop 管理的 Compose 来自这些已保存设置；需要长期保留的设置请在「容器」页修改。导入已有容器会读取其 OneBot 连接，外部项目的挂载、网络和部署文件仍需核对，不能假定读取连接就已迁移全部容器配置。

## 原生 Bot 的访问范围

新建 HTTP、SSE 和正向 WebSocket 监听默认使用 `127.0.0.1`。编辑连接时可开启「允许主机外部访问」，确认风险后改为 `0.0.0.0`；关闭则恢复回环监听。高级监听 IP 仍可手动填写，填写外部地址也需要确认。已有连接保留原地址。

跨服务器的一键对接会自动建立 SSH 隧道，无需为了对接而公开监听端口，详见[应用端对接](app-instances.md#对接-bot)。

## 启动失败怎么查

1. **看失败阶段**：分清安装任务失败、进程退出、QQ 未登录、WebUI 不可用或鉴权失败。Bot 卡片、任务队列和日志会给出各自的状态。
2. **原生部署查依赖**：先在组件页检查 QQ 与运行时，补齐提示缺失的系统库。使用终端时，按实际安装路径检查程序，不沿用其他主机的固定目录。
3. **Docker 查容器**：在这台主机的终端执行以下只读检查，确认 Docker 可用、容器是否退出、端口如何映射。

    ```bash
    docker info
    docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
    ```

4. **查登录与连接**：进程或容器运行不代表 QQ 已登录。检查 WebUI / QQ 登录入口，以及 OneBot 配置、端口和 token。
5. **查远端访问**：重新测试 SSH 连接，确认安装目录、权限和隧道。遇到下载失败时可检查网络或更换界面提供的镜像源。

## WebUI 提示 token 错误

NapCat Docker 的有效 token 以容器当前使用的 `webui.json` 为准；启动参数里的初始 token 不一定与已有配置一致。Desktop 会读取实际配置，鉴权失败后重新核对。更新后重新连接 Bot；如果仍失败，检查 SSH 用户能否执行 Docker 命令、容器配置是否可读，以及 WebUI 是否提示限流或两步验证。

不要连续手动尝试大量登录。提交日志时隐藏 token、密码和通知密钥。

## 在 WebUI 修改的连接被还原

Desktop 启动远端 Bot 时会按已保存配置写入 OneBot 连接。在 WebUI 修改后，打开这个 Bot 的「配置 → 连接」，点击「从远端读取」，核对差异并保存到 Desktop。

## Desktop 退出后继续运行和通知

远端任务由远端主机运行，SSH 断开后应分别核对远端进程状态和通知状态。需要 Desktop 退出后继续值守时，在「组件」页选择远端主机并安装 [ncd-watch](ncd-watch.md)。它是独立发布的组件，升级 Desktop 不会自动升级远端二进制。
