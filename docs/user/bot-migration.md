# 迁移到另一台服务器

Bot 卡片右上角菜单 → **迁移到服务器** → 选择已经登记的目标服务器。

检查页会列出随迁的应用端和不能继续的原因。确认后，Desktop 准备目标环境，停止旧端，打包项目并通过本机中转到目标机，校验归档与 SQLite，重建依赖，再切换协议端和应用端的位置。通常只需选择服务器和确认迁移；QQ 需要重新登录时，点击迁移窗口的「登录 QQ」。

目前支持 Linux 原生部署的 NapCat / SnowLuma 冷启动，以及已关联的 NoneBot2、Karin 项目。NoneBot2 需要 `uv.lock`，Karin 需要 `pnpm-lock.yaml`。依赖按目标机重新安装，因此可以在支持的 CPU 架构间搬迁项目。Docker、SnowLuma 热注入、仍由值守自动重登的账号，以及其他应用框架会在预检时阻断。

只搬 NCD 已关联的项目目录；`.venv`、`node_modules`、缓存和 NCD 进程记录不会搬。业务代码、配置、插件、数据库、Git 历史和空目录保留；配置中以原项目目录开头的路径会改为新目录。QQ 的共享用户目录不会覆盖到目标机，需要时重新扫码。项目外数据库、Redis、额外的 systemd 服务、外部软链接需先单独处理；未纳入 NCD 的应用不会自动随迁。

旧目录和两端快照保留，不自动删除。开始之后可以关闭对话框，保持 Desktop 运行；重新打开菜单能查看当前记录。Desktop 意外退出后会暂停未完成的交接，避免自动启动两端。

需要恢复旧端时，在迁移记录里选择**回退到旧服务器**。如果目标已经启动，须确认目标产生的新数据不会自动回拷。回退会先核实当前端停止，再还原原配置及启动状态；目标目录仍保留。

原先运行的协议端需确认 QQ 在线，应用端检查进程与监听端口；原先停止的实例保持停止。等待扫码时仍会检查目标进程，若协议端或应用端已经退出，迁移记录会提示检查日志或回退。实际插件业务与消息收发仍需迁移后发送一条消息确认。
