# SnowLuma 扫码登录

简化扫码默认开启，Bot 启动后点击卡片上的「扫码登录」，使用手机 QQ 扫码并确认。旧配置中明确关闭的设置会保留；可在 Bot「配置 → 高级」中关闭本机或远端的全局开关。

| 部署方式 | 获取二维码 | 回退入口 |
| --- | --- | --- |
| Windows 原生 | UIA 登录控件定位与单窗口捕获 | QQ 原窗口 |
| Linux SSH 原生 | AT-SPI 登录控件定位与 X11 窗口区域捕获 | VNC |
| 官方 SnowLuma Docker | 容器内同用户、同显示环境的 AT-SPI 与窗口捕获 | VNC |

用户打开扫码窗口时才开始取图。首次打开会切换至 QQ 原来的扫码页；过期后手动刷新，已扫码时停止取图并禁用刷新，等待手机确认。登录成功后立即清空二维码并停止扫码辅助。QQ 主界面已打开但 SL 尚未确认账号时，显示「等待 SL 确认」，不再取图。

关闭窗口、切换 Bot、隐藏扫码页面、停用功能或停止 Bot 都会取消请求并清空图片。单次请求与整个扫码会话均有超时；无法确认辅助请求已退出时会显示清理异常，仍可使用回退入口。手机取消后需要重新扫码时，关闭扫码窗口后再打开。

默认开启和设置变更只在下次冷启动 QQ 时准备能力，不会自动重启已经运行的 QQ 或容器。Windows 服务器需要 Desktop 与 QQ 在同一可用桌面会话；Linux 需要 Python 3、AT-SPI、X11 和可用的会话 D-Bus。窗口被遮挡、最小化、依赖缺失、Wayland 或布局不兼容时使用 QQ / VNC。默认开启不会为缺少依赖的主机临时联网装包。

Docker 只在冷启动时为受支持的镜像准备同用户的无障碍启动环境；不会为扫码重建正在运行的容器。启动包装和挂载目录保留供后续重启，扫码取消或成功不会破坏 QQ 的正常启动。自定义镜像保留 VNC 登录；真实 Docker 手机扫码与消息收发仍需单独验收。

扫码辅助通过系统控件接口操作 QQ 原登录流程，不修改 QQ 或 SL 源文件，不追加扫码入口替换、原生库注入或登录回调监听。SL 自身仍使用原有 hook。二维码仅经私有通道保存在内存，不保存到文件、日志或浏览器缓存，不开放公网端口；系统接口方式不能保证 QQ 风控概率降低。
