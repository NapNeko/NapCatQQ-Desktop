这是针对远端 SSH / Docker 管理的热修版本，处理「SSH 和容器管理正常，但 WebUI 提示 token 错误、调试台无法鉴权，日志反复提示刷新登录凭证失败」的问题（[#154](https://github.com/NapNeko/NapCatQQ-Desktop/issues/154)）。

### 更新内容

#### 修复

- **远端 WebUI token** — 优先读取容器正在使用的 `webui.json`，避免已有配置与 Desktop 缓存、容器启动参数不一致时，打开 WebUI 和使用调试台仍带着旧 token。首次读取失败或鉴权被拒后会定期重新核对；容器配置恢复可读后，也能继续同步
- **登录失败与重复告警** — 正确识别 NapCat 返回的 token 错误、登录限流和两步验证要求，不再把这些响应一律当成解码失败。登录失败后按原因退避重试，减少短时间内反复登录触发限流，以及同一错误持续刷屏
- **ncd-watch 更新** — 更新远端监控组件时先上传到暂存文件，再替换可执行文件，避免直接覆盖运行中的程序。改进非 root 用户的停止与启动流程；启动失败会返回明确错误，不再显示更新成功

#### 改进

- **Bot 状态** — 卡片会区分「WebUI 鉴权失败」「WebUI 登录受限」「WebUI 需两步验证」和「WebUI 不可用」。鉴权恢复后清除旧提示，刷新页面也能恢复当前状态

### 升级说明

安装 3.4.2 后，重新打开 Desktop，让远端会话重新连接并读取容器配置。

使用远端 ncd-watch 的用户，请同时在组件管理中更新到 **ncd-watch 0.2.7**；它会复用 WebUI 登录凭据，减少后台监控反复登录造成的限流。ncd-watch 是独立组件，升级 Desktop 不会自动替换远端二进制。
