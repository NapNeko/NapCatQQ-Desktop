改善 Linux 桌面的容器管理与日志目录打开体验，重新整理 Docker / Podman 的切换交互。

### 更新内容

#### 修复

- **日志目录** — Linux 打开日志位置时隔离 AppImage 的库和启动环境，异步等待文件管理器；失败会显示提示，并提供“复制目录”作为替代入口。#178
- **容器引擎切换** — Docker / Podman 改为状态卡内的并列选项，使用应用主题，避免原生下拉菜单文字不清、弹窗脱离主窗口。切换期间禁用环境安装、镜像拉取和管理动作，等新引擎状态返回后再恢复。#179
- **Podman Compose** — 用不初始化运行时的 `podman --version` 判断安装状态；Compose 包装命令不可用时回退到独立的 podman-compose，探测、启动和停止使用同一 provider，保留当前用户的容器存储。无法使用时记录两条探测路径的具体错误；引擎和 Compose 已安装、仅运行环境异常时直接显示原因，不再反复装包或请求 sudo。#181
- **Podman 兼容命令** — Linux 选择 Docker 时识别 podman-docker 的兼容命令，提示显式选择 Podman，不再套用 Docker 模板、sudo 或安装流程；关闭兼容警告后仍可识别。#183
- **本机容器管理** — Linux 本机没有 SSH 服务器档案时，也能进入容器管理；缺少 Compose 时仍可管理已有容器，未就绪的入口显示禁用原因。#182

#### 改进

- **界面文案** — 统一使用“容器部署 / 容器管理”，环境状态按当前引擎显示，切换失败时保留原选择。
- **问题反馈** — 补充本机 Linux 原生部署、Docker / Podman 和安装包选项，更新 Linux 客户端使用说明。

#### 说明

- Linux 桌面目前仅有 Ubuntu 验证条件。维护者没有 Fedora 等其他发行版和相关桌面组合的实机适配条件；若问题仅在这些环境出现，暂无法继续做专项适配，请先在 Ubuntu 上确认是否同样复现。
