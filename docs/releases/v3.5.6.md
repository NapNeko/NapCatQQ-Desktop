本次更新完善 NapCat 与 SnowLuma 的 Docker 部署，新增监听端口可自动配置容器映射，并提供持久化的容器设置入口。

### 更新内容

#### 新增

- **Docker 容器设置** — 在 Bot 配置页查看自动生成的端口映射，调整宿主机端口或添加额外映射，并设置环境变量、重启策略和内存上限。
- **访问范围控制** — Docker 默认只发布到宿主机回环地址，可确认风险后开启 `0.0.0.0`；原生 OneBot 监听也提供外部访问开关，新建监听默认回环，手动填写外部地址同样会提示风险。
- **Docker 一键对接** — 支持正向与反向 WebSocket、同机及跨服务器应用端，自动配置端口映射和 SSH 转发，无需公开 OneBot 端口。

#### 改进

- **端口自动配置** — 根据启用的 HTTP、SSE 和 WebSocket 服务端补齐 Docker 发布端口；保存运行中的 Bot 时自动重建容器并恢复连接，停止中的 Bot 在下次启动时应用。
- **配置校验** — 保存前提示端口重复、超出范围及无效容器设置，避免启动时才发现配置错误；用户设置随 Bot 配置保存，后续启动继续使用。

#### 修复

- **OneBot 调试台** — 支持 Docker 中新增的监听端口与自定义宿主机映射。
- **容器协议配置** — 修复 SnowLuma 的协议配置未同步至容器数据卷的问题，并让容器内的监听地址可通过端口映射访问。
- **隧道恢复** — 主机重连时同时检查关联 Bot 与应用端，避免复用已经断开的隧道，并核验常驻转发的实际就绪状态。

#### 说明

- **应用容器设置** — 运行中修改端口或容器设置会短暂断开连接；容器重建保留现有数据卷。若应用失败，配置仍会保存，可修正冲突后重新启动。
- **默认重启策略** — 后续创建的 NapCat / SnowLuma 容器统一默认使用 `unless-stopped`，手动停止后不会因 Docker daemon 重启而自行启动；可在容器设置中调整。
- **默认发布范围** — 后续创建或重建的容器默认只发布到 `127.0.0.1`。已有跨机直连如需继续使用，请先在容器设置中开启外部访问；一键对接会自动使用隧道。
- **对接隧道** — 本机与远端组合需要 Desktop 在线；两远端之间使用主机常驻隧道。Docker 反向对接需要宿主机 SSH 工具和自身 SSH 连接可用，主机重启后重新连接 Desktop 恢复转发。
