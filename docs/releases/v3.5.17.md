修复旧 SnowLuma 容器升级重建时，原有运行配置和 WebUI 设置可能不再被读取的问题。

### 更新内容

#### 修复

- **旧容器数据迁移** — 重建前备份旧数据目录，将运行配置、WebUI 设置、协议同意记录和其他账号数据补入持久卷，再启动 SnowLuma。
- **已有配置保留** — 迁移不会覆盖新持久卷中已有的文件，重复启动也不会把已修改的配置还原为旧版本。
- **失败恢复** — 数据复制或迁移失败时保留旧容器和完整备份，排除磁盘空间、权限等问题后可以重试。

#### 说明

- 已使用 `/app/snowluma-data` 持久卷的实例沿用原有数据。旧容器备份位于部署项目目录的 `snowluma-legacy/<旧容器 ID>`，确认运行配置、WebUI 和账号正常前请保留。
- 本次已使用隔离 Docker 数据验证可写层与匿名卷迁移；Podman、SSH 和官方 SnowLuma 镜像的完整启动仍需实机验证。Fedora KDE 的输入冻结与删除卷反馈仍在调查。
