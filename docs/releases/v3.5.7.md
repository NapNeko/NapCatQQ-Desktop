本次更新集中改进远端 NapCat、SnowLuma 的状态恢复和启停稳定性，并完善 Docker 部署入口。

### 改进

- **远端状态刷新**：复用已核验的进程与连接，减少重复远端探测；NapCat 日志改为有界增量读取，避免反复下载整个日志。
- **启动检查**：批量核对远端 QQ 系统依赖，减少逐项 SSH 往返；组件安装结束后及时重查库存和启动条件。
- **Docker 部署**：从管理页直接进入当前主机的部署区，新建 Bot 自动填入主机和框架；统一引擎不同状态的卡片布局，应用端列表优先展示 NeoBot。

### 修复

- **启停卡住**：停止失败、异常或超时后退出“停止中”；重复启动、启动中停止和断线后的迟到响应按实例代次处理，避免旧结果覆盖当前状态。
- **SSH 稳定性**：限制短命令并发，并隔离单个 SSH 通道和 SFTP 子系统故障，避免拖垮整条连接。
- **SnowLuma WebUI**：根据实际 Node 进程的监听 socket 确认端口，核对密码文件与进程身份；打开 WebUI 时通过系统剪贴板复制密码。
- **noVNC**：按目标 QQ 的图形会话建立连接，并验证代理后的 VNC 握手；WebUI 与 noVNC 分别恢复。
- **系统 QQ 入口**：原生入口已正确时不再重复写入；需要修改系统安装目录时使用已有提权流程。
- **提示条**：修正 InfoBar 的定位和进退场溢出，避免动画出现横向滚动条。

### 说明

- 原有系统服务管理的 QQ 如果会自动重启，Desktop 会明确提示服务归属，避免误停后又被服务拉起。
- 远端 SnowLuma 的实际登录状态取决于 QQ 会话；等待扫码会显示“待扫码”，不会当成已经登录。
