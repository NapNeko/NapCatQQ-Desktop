本版新增 Windows 原生远程管理，加入独立的网络设置页，并统一扫码弹窗、密钥输入与圆角样式。

### Windows 原生远程管理

- **连接 Windows 主机** — 通过 OpenSSH 识别目标系统，支持 PowerShell 终端、文件传输、端口隧道和 Windows 路径。添加主机时可以自动识别系统，也可以明确选择 Windows。
- **远程托管代理** — 安装包随附 Windows 远程代理，可在主机管理页启用或重新部署。机器服务与用户桌面工作进程分别处理后台托管和 QQ 会话，按 Windows 用户身份隔离组件、应用与数据目录。
- **原生 Bot 与应用端** — 接入 Windows 目标机的组件安装、库存、NapCat/SnowLuma 启停、配置、日志、WebUI 和应用端监督；补齐主机指标、定时重启及值守接线。
- **会话状态可见** — 管理页显示目标身份、托管服务、用户桌面和工作进程状态；等待登录、锁屏、多会话及代理待更新时给出对应操作。
- **Windows SSH 兼容修复** — 修复真实 Server 2022 上命令输入阻塞、长命令传输停滞和 PowerShell 启动进度混入命令输出的问题。

目标机需要启用 OpenSSH Server，首次部署代理需要管理员账户；QQ 运行和扫码还需要该账户登录桌面。SSH 登录不能代替桌面登录。详见 [Windows 远程管理](https://github.com/NapNeko/NapCatQQ-Desktop/blob/main/docs/user/windows-remote.md)。

本版已通过代码与本机隔离验证，并在 Windows Server 2022 上实测 SSH、SFTP、命令、隧道和代理探针。服务部署与升级、用户会话恢复、QQ 扫码及完整应用生命周期仍待真实远端验收。

### 网络设置

- **统一网络入口** — 在「设置 → 网络」选择系统代理、直连或手动代理；支持 HTTP、HTTPS、SOCKS5/SOCKS5H、代理认证与排除地址。保存后用于新请求，已开始的下载沿用原配置。
- **下载线路可选** — GitHub 与 Node.js 下载分别支持自动择优、仅原站、指定内置或自定义镜像；指定线路失败时保留错误，不擅自换源。
- **草稿连接测试** — 保存前测试当前代理与线路，查看 HTTP 结果和响应耗时。GitHub API 访问方式与个人 Token 也移至网络页。
- **凭据隔离** — 代理密码保存在系统密钥库或本机加密存储，不写入普通设置文件，不随配置 ZIP 导出。SSH、远端工具和本机 WebUI 仍使用各自的网络路径。

### 界面调整

- NapCat 与 SnowLuma 共用扫码弹窗布局，统一二维码、等待手机确认、过期和异常状态的呈现。
- 密码与密钥输入默认隐藏内容，使用统一的显隐按钮，减少不同页面的操作差异。
- 调整方正、标准和圆润三档圆角，设置中的预览与实际控件使用同一组数值。

### 聊天与启动体验

- 修复好友和群聊文件消息的下载入口，兼容不同协议版本的文件标识和消息直链。
- 消息多选、键盘焦点和搜索定位的边框贴合图片、视频、语音与文件卡片，减少媒体周围的空白。
- 语音条补齐播放 / 暂停、进度拖动、时长、音量和倍速控件，首次点击即可加载并播放，失败后可重试。
- 修复主窗口与聊天窗口长期隐藏后可能出现的交接失败，交接时临时唤醒后台页面并保护草稿恢复。
- 远端 SnowLuma 批量启动复用同一主机的共享服务，减少重复初始化、SSH 探测与密码校验；服务失效或 SSH 重连时重新检查。

### 配套值守

配套发布 **ncd-watch 0.3.0**。Windows 值守由随 Desktop 部署的远程代理承载；Linux 仍使用独立的 ncd-watch 二进制。Desktop 升级不会自动替换 Linux 主机上的 ncd-watch。
