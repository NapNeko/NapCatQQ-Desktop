完善 Docker / Podman 同机共存，补齐 AppImage 环境探测和 NapCat 加载诊断，并修复 AstrBot 安装失败后的重试。

### 更新内容

#### 修复

- **容器引擎共存** — 新建容器 Bot 时可单独选择 Docker 或 Podman；已有 Bot 自动记住原引擎，切换主机的管理视图不再要求移除 Bot，也不会迁移或重建原容器。
- **容器管理与回读** — 容器、镜像和就绪状态按主机与引擎分别缓存，启停、日志、WebUI 凭据、扫码、容器终端和远端 OneBot 配置回读使用实例所属引擎，避免同机两个引擎混用数据。
- **Podman Compose** — 清理 AppImage 子进程继承的包内 Python 和模块路径；探测失败时直接显示两种 Compose 入口的具体原因。provider 已存在但执行失败时结束补全流程，避免重复装包或索取 sudo；Podman 始终保留当前用户的容器存储。#181
- **NapCat 加载** — 正确处理运行时路径中的引号、空格和 URL 保留字符；指标探针加载失败后仍继续导入核心，并增加加载入口、核心导入成功及失败日志。本机和远端 Windows 使用一致的诊断行为。#190
- **AstrBot 安装重试** — 新建安装失败留下虚拟环境时，重试会清理并重建该实例的虚拟环境，已有配置的升级和导入流程保留原行为。#184

#### 说明

- rootless Podman 的用户网络仍不支持自动绑定宿主机网桥来转发回环应用端口；相关反向对接需使用容器可达的应用监听地址手动配置。
- #181 的 Fedora / Gear Lever 整窗冻结与 #190 的 Windows 原生组件加载失败尚未在维护环境复现，本版补齐了相关健壮性和诊断，仍需对应故障环境验证。
