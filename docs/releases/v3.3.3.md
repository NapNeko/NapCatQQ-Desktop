本版主线是配置搬家收尾：「设置 → 数据」的导出包现在完整带上框架配置与界面偏好，导入逐项预检、失败整体回滚、条件不够先存待恢复；另收紧了 Koishi 备份范围，修复 AstrBot 插件市场误拦。本版不含聊天相关改动（仍在开发中）。

### 更新内容

#### 新增

- **完整配置备份（v2）** — 导出 ZIP 在原有基础上新增：应用端实例档案（含领养时保存的回滚快照）、七个应用端框架的配置原文（Karin / NoneBot2 / AstrBot / MaiBot / Koishi / 云崽 / NeoBot 的核心设置、模型与插件配置，麦麦自定义提示词及历史版本）、界面与终端偏好、API 调试台工作区、SnowLuma 全局设置。框架配置按原文件保存，注释、格式和自定义字段原样保留；只收文本配置，程序本体、依赖、数据库和聊天消息记录一律不进包
- **框架配置恢复** — 导入或迁移时逐实例预检：目标目录须属于对应框架、实例须已停止、远端恢复核对 SSH 连接身份；写入一半失败整体回滚。实例还没装、正在运行或远端连不上时，配置先存为「待恢复副本」，装好、停妥或重连后在数据页一键「重试恢复框架配置」，待恢复副本也随下一次导出一起走

#### 修复

- **Koishi · 配置备份收紧** — 备份不再收 Koishi 的 `package.json` 可执行清单（其 `scripts.start` 会在启动时执行，篡改过的配置包借「导入 + 重启」即可运行任意命令）；白名单保留 `koishi.yml` 与 `.env`
- **AstrBot · 插件市场误拦「身份不符」** — 插件 `metadata.yaml` 字段尾部的「# 作者」式行内注释此前被当成值的一部分，拼出的插件身份与市场目录对不上，安装被拦；现在按 YAML 规则正确剥离注释（引号内的 # 仍算内容）
- **Windows · 导出覆盖必报错** — 导出选「覆盖已有文件」时，Windows 不允许直接覆盖改名，必报「替换导出 ZIP 失败」；现在先挪开旧档、写入新档再清理，任何一步失败目标处仍保住完整的一份
- **导入 · 拒绝实例共用安装目录** — 手改过的 `app-instances.json` 可让多个实例指向同一安装目录，起停、恢复、删除会互相打到对方文件；导入预检现在按主机加安装目录去重直接拒绝
- **Windows · 框架恢复预检认短路径别名** — 实例目录落在带 `RUNNER~1` 式短名称别名的路径下时（部分临时目录如此），恢复预检此前对不上目录名；现在按原始路径逐段核对，长名短名都认，符号链接检查不放松
- **界面偏好恢复不留残值** — 导入缺省快照后，终端布局、Bot 排序等没写进快照的项会残留旧值却报告「偏好已恢复」；现在缺省项一并清回默认，写盘失败时也随回滚复原

#### 说明

- 配置包只含配置：框架与插件程序本体、系统密钥库（SSH 私钥与密码、GitHub Token）不随包恢复，换机需另行安装与配置；配置原文里的 OneBot token、模型 API Key 等仍随文件保存，请妥善保管配置包
- 旧版 ZIP 与扁平配置文件夹继续支持导入；新包为 v2 格式，沿用旧版四个文件名
- 实例尚未安装、正在运行或远端暂不可达的，导入后记得在「设置 → 数据」点「重试恢复框架配置」
- 本版数据路径与既有配置不动；覆盖安装即可
