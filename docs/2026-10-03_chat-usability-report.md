# 聊天体验对照与优化

调研日期：2026-10-03。对照 NapCatQQ Desktop `89eeda41` 的聊天页与 Stapxs QQ Lite 3.5.0。结论是先减少常用操作的中断：列表直接管理会话、消息原地操作、搜索用键盘定位、发送后接着输入。保留 NapCat 主窗口的双栏、群消息盒子与现有视觉规范。

## 体验范围与方法

- Stapxs：使用官方 README 提供的 `ssqq-web` 本地运行 3.5.0 Web 发布包；源码参考 `next` 分支提交 `7a895b964a67faf72f912370eb769adce16e37cc`。两者版本来源分开记录，未假定发布包与分支逐行一致。
- NapCat：使用本机已安装组件和既有账号配置启动后端。两边通过仅监听回环地址的临时只读适配器读取同一账号的最近会话、联系人、群成员和消息历史。
- 我们的界面：运行当前工作树的 React 页面，通过临时 Vite 插件将浏览器预览的聊天数据入口接入真实 OneBot 返回。账号、历史和消息渲染是真实数据；Tauri IPC、桌面文件选择器及归档磁盘写入没有在这条浏览器链路中验收。
- 真实账号操作限于读取、打开会话、搜索、查看菜单与未发送的引用。只读适配器拒绝发送、上报已读、撤回和管理类动作。连续发送与草稿变动在独立的合成预览数据中验证。
- 检查桌面双栏与窄窗口返回列表；不把联系人内容、聊天原文、凭据或真实账号截图纳入仓库文档。临时适配器和第三方源码均位于仓库外。

## 已确认的差距

| 操作 | Stapxs | 我们的基线 | 本轮处理 |
| --- | --- | --- | --- |
| 识别会话日期 | 实测同一条旧会话显示月日，近期显示星期/时刻 | 旧会话也只显示 `HH:mm`，容易误认作今天 | 显示今天时刻、昨天、月日、跨年日期，并提供完整时间 |
| 列表管理 | 源码和真实界面提供会话上下文菜单 | 置顶入口在资料面板，清未读需要进入会话 | 会话右键置顶/取消置顶、标记已读；已读仅改变本地未读数 |
| 寻找并打开会话 | 有联系人和会话查找入口 | 输入搜索后仍需鼠标点选 | 列表方向键、Enter 打开；Ctrl/Cmd+K 聚焦搜索 |
| 消息原地操作 | 实测右键显示回复、复制、提及、转发、多选等 | 消息侧边只有回复、复制和失败恢复 | 复用产品 ContextMenu，加入回复、复制、提及和失败恢复，保留侧边按钮 |
| 查找消息 | 有搜索模式及返回消息位置的操作 | 当前已加载范围，Enter 无动作、结果无命中高亮 | 键盘选择与定位、字面关键词高亮、明确搜索范围 |
| 搜索较早内容 | 源码支持已加载/本地历史两种搜索范围 | 必须退出搜索后上翻加载，最多显示最近 50 个结果 | 搜索内显式加载更早一页、错误重试、逐步显示更多结果 |
| 连续输入 | 紧凑输入区，操作围绕输入区展开 | 预览实测点击发送后焦点变为页面 BODY | 发送及取消引用后回到编辑框，菜单提及/回复衔接编辑框 |
| 群工具与完整消息操作 | README/源码含群文件、公告、精华、多选、转发、撤回 | 已有资料与成员、合并转发读取，缺少相应完整管理/发送流程 | 列为后续工作，未宣称本轮已补齐 |

## 设计与实现约束

延续现有 surface、text、brand、border 语义 token，沿用页面字体、字号和圆角。会话菜单复用共享 Radix ContextMenu，搜索命中用轻量高亮，键盘选中态与鼠标悬停态保持一致。窄窗口仍使用“列表 → 会话 → 返回”的结构。

聊天继续使用现有独立订阅和 `ChatAccountStore`，复用 OneBot 调试基础中的消息段、提及组装、虚拟列表与贴底逻辑。不引入第二套聊天状态；不复制 Stapxs 的 AGPL 实现代码。本轮只参考可观察的交互行为，自行实现。

草稿仍按账号和会话隔离并保留在内存。标记已读不切换会话、不清空草稿、不调用上游已读接口。搜索每次只显式读取一页历史，避免自动遍历整段群历史。新消息与加载更早历史时保持搜索词和当前选择；中文输入法确认键不触发消息定位或发送。

## 验收路径

1. 在聊天列表搜索联系人，按上下方向键和 Enter；用 Ctrl/Cmd+K 返回列表搜索。右键另一会话置顶、标记已读，确认当前会话和草稿不变。
2. 打开群会话，右键消息回复/提及；确认原有文字、附件与引用不会被意外替换，输入框能继续输入。
3. Ctrl/Cmd+F 搜索，确认关键词高亮、上下键选中、Enter 定位、Escape 返回；用中文输入法确认候选时不跳转。
4. 在搜索面板读取更早一页，确认搜索词仍在；模拟错误时能重试，断线时不能加载，已到最早时有明确提示。
5. 在合成预览中点击发送，直接输入下一句；取消引用后继续输入。真实账号不发送测试消息。
6. 检查桌面宽度和窄窗口：菜单不越界，搜索状态/历史按钮可见，输入区与返回列表流程可操作。

## 后续优先级

1. 完整发送闭环：本人消息撤回、撤回后重新编辑、单条/多条转发。需要协议能力判定、失败状态和真实测试目标。
2. 群内容查阅：群文件、公告、精华消息，在当前资料面板的信息结构上扩展。
3. 更深历史搜索：当前模型只缓存有限近期消息；若需要跨全部历史，先确定本地索引、保留周期、媒体索引与迁移方案。

## 验证结果

- 完整前端测试：`pnpm exec vitest run --config src-ui/vitest.config.ts --dir src-ui --silent --maxWorkers=4 --minWorkers=1`，164 个文件、1483 项测试全部通过。
- `pnpm run typecheck`、`pnpm run build`、`git diff --check` 通过。生产构建仍提示已有的大体积共享 chunk，不影响构建产物生成。
- 真实历史：列表旧日期显示为月日；在搜索面板中从 50 条加载到 58 条并到达最早消息，搜索词与结果保留，Enter 退出搜索并定位。右键提及后编辑框聚焦，光标位于新增提及末尾；检查后清空草稿，未发送。
- 合成预览：会话菜单标记已读、键盘搜索并打开、窄窗口 Ctrl+K 返回并全选搜索内容、点击发送后焦点留在编辑框均通过浏览器操作验证。
- 视觉检查：1280×860 桌面双栏及 420×820 窄窗口；窄窗口文档宽度与滚动宽度均为 420，没有横向溢出。搜索结果列表独立滚动，扩展结果和历史按钮保持可见，输入区可以操作。
- 单元测试覆盖中文输入法、结果变动/撤回、超过 50 条命中、断线与历史读取错误、同名提及、草稿/附件保留、剪贴板失败及菜单键盘入口。此次没有 Rust 代码变更，未重新运行 Rust 全量测试。
